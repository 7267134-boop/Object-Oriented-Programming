6.1 המחלקה Object: ארכיטקטורת השורש, מנגנון ההדפסה, שוויון וגיבוב, שייכות ושכפול

הכרת מחלקת השורש שממנה יורשות כמעט כל המחלקות ב-Smalltalk: מדוע אסור להוסיף לה משתני מופע, כיצד פועל צינור ההדפסה הדו-שלבי (printString מול printOn:), מהו עצם המשערך את עצמו (Self-Evaluating), חוזה השוויון וה-Hash, בדיקות שייכות למחלקה, שלוש רמות השכפול בזיכרון וטיפול במצבים חריגים.

🧠

מודל מנטלי ועיקרון מנחה: תבנית Template Method וחוזה השורש של כל העצמים

המחלקה Object (שמעליה נמצאת ב-Squeak רק המחלקה המינימלית ProtoObject) מגדירה קרוב ל-400 מתודות המהוות את המכנה המשותף של כל עצם במערכת. כדי להבין איך Object מתפקדת עבור כל מחלקה עתידית מבלי להכיר את פרטיה מראש, עלינו להפנים שלושה עקרונות ליבה הנדסיים:

1. אפס משתני מופע ב-Object

למחלקה Object אין משתני מופע כלל ואסור להוסיף לה משתני מופע. הסיבה לכך היא שמחלקות ליבה כמו SmallInteger יורשות ממנה, והמכונה הווירטואלית (VM) מסתמכת על ייצוגן הישיר בזיכרון ללא שדות מצביעים.

2. תבנית Template Method

מתודות מעטפת ב-Object כמו printString, ~= ו-copy אינן נדרסות בתת-המחלקות! הן קוראות למתודות ממוקדות (printOn:, =, postCopy) שאותן תת-המחלקות דורסות.

3. חוזה השוויון והגיבוב

ברירת המחדל של = ב-Object היא בדיקת זהות מצביעים (==). כל מחלקה שדורסת את = לשוויון תוכן חייבת לדרוס בהתאמה גם את hash כדי לא לשבור מילונים וקבוצות.

1. ארכיטקטורת השורש (ProtoObject → Object), מנגנון ההדפסה ו-Self-Evaluating

הפרדת האחריות בין printString ל-printOn: aStream, הדפסת נקודות ב-Point ועצמים המשערכים את עצמם

מעבדת הדפסה

בראש היררכיית המחלקות של Smalltalk ניצבת המחלקה Object. בסביבת העבודה Squeak הוצבה מעליה מחלקת-על מינימלית בשם ProtoObject (שמחלקת-העל שלה היא nil), המרכזת אך ורק את הפרימיטיבים הבסיסיים ביותר שקיומם הכרחי לכל עצם (כגון בדיקת זהות ==, בדיקת isNil ומתודת האתחול הריקה initialize). מאחר שכמעט כל המחלקות במערכת יורשות במישרין או בעקיפין מ-Object, היא מגדירה את ההתנהגות הכללית של עצמים. למחלקה Object אין משתני מופע כלל, ואסור להוסיף לה משתני מופע — שכן הוספת שדה ל-Object תשנה את מבנה הזיכרון של כל העצמים במערכת ותשבור מחלקות כמו SmallInteger שהמכונה הווירטואלית (VM) מסתמכת על המבנה הפנימי הקבוע שלהן.

🖨️מתודת ברירת המחדל Object >> printOn: aStream

הדפסת עצם מתבצעת על ידי שליחת ההודעה האונרית printString לעצם. מתודה זו יוצרת זרם כתיבה פנימי (WriteStream), שולחת לעצם (self) את ההודעה printOn: aStream, ומחזירה את המחרוזת שנכתבה לזרם. ב-Object מוגדרת printOn: כך שהיא משרשרת לזרם (באמצעות nextPutAll:) את הקידומת 'an ' (אם שם המחלקה מתחיל באות תנועה, isVowel) או 'a ', ואחריה את שם המחלקה: 

Object >> printOn: aStream
    "Append to the argument, aStream, a sequence of characters that identifies the receiver."
    | title |
    title := self class name.
    aStream
        nextPutAll: (title first isVowel ifTrue: ['an '] ifFalse: ['a ']);
        nextPutAll: title

למשל: Object new printString יחזיר 'an Object', ואילו Browser new printString יחזיר 'a Browser'.

📍דריסת printOn: במחלקה Point ומלכודת המינוס

כדי להעניק לעצמים ייצוג טקסטואלי משמעותי, תת-מחלקות דורסות את printOn: aStream (ולא את printString!). במחלקה Point (בעלת משתני המופע x ו-y) המתודה נדרסת באופן רקורסיבי-פולימורפי: 

Point >> printOn: aStream
    "The receiver prints on aStream in terms of infix notation."
    x printOn: aStream.
    aStream nextPut: $@.
    (y isNumber and: [y negative]) ifTrue:
        [aStream space].
    y printOn: aStream
מדוע חיוני המשפט (y isNumber and: [y negative]) ifTrue: [aStream space]?
אילולא הוספת הרווח כאשר y שלילי, הנקודה 3 @ -4 הייתה מודפסת כ-3@-4. בשפת Smalltalk הרצף @- מפוענח ע"י המהדר כאופרטור בינארי יחיד בשם @- (שאינו קיים!), במקום ההודעה @ שאחריה המספר השלילי -4. הוספת הרווח מייצרת '3@ -4' שהוא ביטוי Smalltalk חוקי לחלוטין!

✨ עצמים המשערכים את עצמם (Self-Evaluating Objects) וקדימות הדפסה בחלון העבודה

כאשר אנו מסמנים ביטוי בחלון העבודה (Workspace) ולוחצים Ctrl+p (print it), המערכת מעריכה תחילה את הביטוי כולו ורק אז שולחת לעצם המוחזר את ההודעה printString. לכן אין צורך להקיף ביטוי בסוגריים לפני Ctrl+p. לעומת זאת, אם נכתוב בקוד עצמו את הביטוי 3 @ 4 printString ללא סוגריים: מכיוון שלהודעה אונרית (printString) יש קדימות גבוהה יותר מהודעה בינארית (@), הביטוי יתפרש כ-3 @ (4 printString), כלומר 3 @ '4' (נקודה שקואורדינטת ה-y שלה היא המחרוזת '4'!), בעוד ש-(3 @ 4) printString מחזיר את המחרוזת '3@4'.

עצם נקרא משערך את עצמו (Self-Evaluating) כאשר ייצוגו המודפס (פלט printString) הוא קוד Smalltalk תקני שכאשר מעריכים אותו מחזיר עצם השווה לעצם המקורי. דוגמאות: מספרים (42, 3/4), תווים ($a), מחרוזות ('hello'), סימבולים (#sym), נקודות (3@4), תחומים (1 to: 5) ומערכים ליטרליים (#(1 2 3)). מערך דינמי {...} הוא Self-Evaluating אם ורק אם כל איבריו כתובים כביטויים שהם Self-Evaluating: למשל, הביטוי {3@4 . 4.5} מדפיס {3@4 . 4.5} ולכן הוא Self-Evaluating; לעומתו, הביטוי {3@4 . 4+5} מדפיס {3@4 . 9} (כי 4+5 חושב ל-9), ומכיוון שפלט ההדפסה שונה מהביטוי המקורי, הביטוי {3@4 . 4+5} אינו Self-Evaluating.

2. זהות (==) מול שוויון (=) וחוזה ה-hash

השוואת מצביעים בזיכרון לעומת השוואת ערכים לוגית, מימוש Point >> = ומדוע דריסת = מחייבת דריסת hash

מעבדת Hash

בשפת Smalltalk קיימת הבחנה חדה בין שתי רמות של השוואה בין עצמים: האופרטור == בודק זהות (Identity) — האם שני הביטויים מצביעים בדיוק לאותו עצם פיזי בזיכרון ה-RAM (ומשלימו הוא ~~). מתודה זו מוגדרת כפרימיטיב ב-ProtoObject ואין לדרוס אותה לעולם. לעומת זאת, האופרטור = בודק שוויון לוגי/ערכי (Equality) — האם שני עצמים מייצגים את אותו ערך (ומשלימו ~= ממומש ב-Object כ-^(self = anObject) not ולכן אין צורך לדרוס את ~=).

ברירת המחדל ב-Object מול דריסה ב-Point

במחלקת השורש Object, ברירת המחדל של = היא בדיקת זהות (^self == anObject), ובהערת התיעוד שלה מופיעה אזהרה מפורשת: 

Object >> = anObject
    "Answer whether the receiver and the argument represent the same object.
    If = is redefined in any subclass, consider also redefining the message hash."
    ^self == anObject

במחלקה Point אנו רוצים ששתי נקודות (3@4) = (3@4) ייחשבו שוות גם כשמדובר בשני מופעים נפרדים בזיכרון: 

Point >> = aPoint
    self species = aPoint species
        ifTrue: [^x = aPoint x and: [y = aPoint y]]
        ifFalse: [^false]

🔑 חוזה השוויון וה-hash (דגש מרכזי בבחינות!)

המתודה hash מחזירה מספר שלם (Integer) המייצג את "תעודת הזהות הלוגית" של העצם ומשמש לחישוב אינדקס המגירה באוספי גיבוב (Set, Bag, Dictionary). החוזה המתמטי קובע:

אם a = b מחזיר true $\implies$ חובה שיתקיים a hash = b hash!

מה קורה אם דורסים את = ושוכחים לדרוס את hash?
המתודה Object >> hash מחזירה את self identityHash (מספר אקראי-קבוע התלוי בכתובת הזיכרון של המופע). לכן שני מופעים נפרדים עם אותו תוכן (למשל שני קלפים זהים c1 = c2) יקבלו ערכי hash שונים, ימופו לשתי מגירות שונות בטבלת הגיבוב של Set או Dictionary, והאוסף לא יזהה שהם שווים!

3. בדיקות שייכות למחלקה (class, isMemberOf:, isKindOf:, respondsTo:)

בדיקת מופע ישיר לעומת עץ הירושה, מלכודת המחלקות המופשטות, ובדיקות isNil / notNil

מעבדת שייכות
מתודה מה היא בודקת / מחזירה? דוגמאות הרצה (4 הוא מופע של SmallInteger) דגשים ושימושים
class מחזירה את עצם המחלקה שממנה נוצר המקבל במישרין. 4 class ➔ SmallInteger
(3@4) class ➔ Point		 מוגדרת ב-Object; נקודת ההתחלה של אלגוריתם ה-Method Lookup.
isMemberOf: aClass מחזירה true אם ורק אם העצם הוא מופע ישיר ובדיוק של aClass (self class == aClass). 4 isMemberOf: SmallInteger ➔ true
4 isMemberOf: Number ➔ false!		 מלכודת בחינה: עבור כל מחלקה מופשטת (כמו Number או Collection), x isMemberOf: Number יחזיר תמיד false כי אין לה מופעים ישירים!
isKindOf: aClass מחזירה true אם העצם הוא מופע של aClass או של תת-מחלקה כלשהי שלה במורד עץ הירושה. 4 isKindOf: SmallInteger ➔ true
4 isKindOf: Number ➔ true
4 isKindOf: Object ➔ true
4 isKindOf: Point ➔ false		 שימושית כשנדרש לוודא שעצם שייך למשפחת טיפוסים (למשל בדיקה שכל איברי אוסף הם מספרים: x isKindOf: Number).
respondsTo: aSymbol מקבלת סימבול של בורר הודעה (עם #) ומחזירה true אם העצם מבין את ההודעה (קיימת מתודה במחלקתו או במחלקות-העל). 4 respondsTo: #+ ➔ true
'hello' respondsTo: #size ➔ true		 בדיקת יכולת התנהגותית (Duck Typing). בתיכנות מונחה עצמים מעדיפים שליחת הודעות ישירה וקישור דינמי על פני בדיקות סוג מפורשות.
isNil / notNil בודקות האם העצם הוא העצם המיוחד nil (מופע יחיד של UndefinedObject). nil isNil ➔ true

4. העתקה ושכפול עצמים (shallowCopy, copyTwoLevel, deepCopy, copy), אתחול וניפוי שגיאות

שיתוף מצביעים מול שכפול עמוק, תבנית copy / postCopy, super initialize ופרוטוקול error handling

מעבדת שכפול

בשפת Smalltalk כל משתני המופע ואיברי המערכים ממומשים כמצביעים (References) לעצמים. לכן, כאשר אנו משכפלים עצם מורכב (כגון מערך שמכיל מערכים), עלינו להבחין בין ארבע מתודות ההעתקה המוגדרות ב-Object:

1. shallowCopy (שכפול רדוד – רמה 1 בלבד)

יוצרת מופע מעטפת חדש (a1 == a2 הוא false), אך מעתיקה אליו את אותם מצביעים בדיוק! תתי-העצמים הפנימיים משותפים לחלוטין ((a1 at: 1) == (a2 at: 1) הוא true): 

a1 := {{'a'. 'b'}. {'c'. 'd'}}.
a2 := a1 shallowCopy.
(a1 at: 1) at: 1 put: 'z'.
"גם a1 וגם a2 השתנו ל: #(#('z' 'b') #('c' 'd')) !"
2. copyTwoLevel (שכפול דו-רמתי – רמות 1 ו-2)

משכפלת את העצם החיצוני (רמה 1) וגם משכפלת בשכפול רדוד כל אחד ממשתני המופע / איבריו הישירים (רמה 2). במערך דו-ממדי {{'a'. 'b'}. {'c'. 'd'}} שינוי ב-(a1 at: 1) at: 1 put: 'z' לא ישפיע על a2! אך במערך תלת-ממדי (עומק 3) תת-המערכים ברמה 3 עדיין משותפים: 

a1 := {{{'a'}. {'b'}}. {{'c'}. {'d'}}}.
a2 := a1 copyTwoLevel.
((a1 at: 1) at: 1) at: 1 put: 'z'.
"ברמה 3 השינוי משתקף גם ב-a1 וגם ב-a2!"
3. deepCopy (שכפול עמוק רקורסיבי מלא)

משכפלת באופן רקורסיבי את העצם ואת כל העצמים המוצבעים ממנו בכל עומק שהוא, ליצירת עץ עצמים עצמאי לחלוטין (חיסרון: סכנת לולאה אינסופית במבנים מעגליים).

4. תבנית copy ו-postCopy (הדרך המומלצת ב-Squeak)

ב-Object מוגדרת copy כ-^self shallowCopy postCopy. ב-Object המתודה postCopy אינה עושה דבר (^self), ותת-מחלקות דורסות את postCopy כדי לשכפל באופן מבוקר רק את השדות הפנימיים שדורשים הפרדה.

🚀 אתחול אוטומטי (initialize ו-super initialize)

ב-Squeak, מתודת המחלקה Behavior >> new יוצרת את המופע החדש (basicNew) ומיד שולחת לו אוטומטית את ההודעה initialize (המוגדרת ב-ProtoObject כמתודה ריקה המחזירה ^self). כאשר תת-מחלקה דורסת את initialize כדי לאתחל את משתני המופע שלה, חובה לפתוח בפקודה super initialize. כדי להבטיח שגם משתני המופע שהוגדרו במחלקות-העל יאותחלו כראוי!

🚨 פרוטוקול ניפוי שגיאות וחריגות (error handling) ב-Object

  • self halt — עוצרת את הריצה ופותחת מיד את ה-Debugger בנקודת הקריאה.
  • self assert: aBlock — תומכת בתכנות לפי חוזה (Design by Contract); מעריכה את הבלוק ואם תוצאתו false מעוררת חריג AssertionFailure.
  • self error: aString — יוצרת ומעוררת מצב חריג מסוג Error עם הודעת הטקסט.
  • self deprecated: aString — מתריעה שהמתודה מיושנת ומפנה למתודה החלופית (למשל doIfNotNil: המעבירה ל-ifNotNilDo:).
  • self subclassResponsibility — מסמנת מתודה מופשטת שחובה על תת-המחלקות לדרוס.
  • self shouldNotImplement — חוסמת מתודה שנורשה ממחלקת-על אך אינה מתאימה לתת-המחלקה (למשל Array >> add: או Set >> at:).

6.1 המחלקה Object: הדפסה, שוויון וגיבוב, שייכות למחלקה ושכפול עצמים

המחלקה Object (שמעליה ב-Squeak נמצאת רק ProtoObject) מגדירה את ההתנהגות המשותפת של כל העצמים. אין לה משתני מופע כלל ואסור להוסיף לה שדות כדי לא לשבור את ייצוג SmallInteger במכונה הווירטואלית.

1. מנגנון ההדפסה (printString מול printOn: aStream) ו-Self-Evaluating

תבנית Template Method להדפסת עצמים וזיהוי עצמים שייצוגם המודפס שווה לעצמם.

איך עובדת הדפסה ב-Object וב-Point?

שליחת printString לעצם יוצרת זרם כתיבה ושולחת לעצם את printOn: aStream. ב-Object נכתב לזרם 'a ' או 'an ' (אם האות הראשונה בשם המחלקה היא תנועה isVowel) ואז שם המחלקה. במחלקה Point נדרסת printOn:: 

Object >> printOn: aStream
    | title |
    title := self class name.
    aStream nextPutAll: (title first isVowel ifTrue: ['an '] ifFalse: ['a ']);
            nextPutAll: title

Point >> printOn: aStream
    x printOn: aStream.
    aStream nextPut: $@.
    (y isNumber and: [y negative]) ifTrue: [aStream space].
    y printOn: aStream

הרווח לפני y שלילי מונע מהמהדר לפרש את 3@-4 כאופרטור לא-קיים @-.

עצם המשערך את עצמו (Self-Evaluating)

עצם הוא Self-Evaluating אם המחרוזת שמחזירה printString היא קוד Smalltalk שכאשר מעריכים אותו מחזיר עצם זהה בערכו:

  • כן (Self-Evaluating): מספרים (5, 3/4), תווים ($a), מחרוזות ('hi'), סימבולים (#s), נקודות (3@4), תחומים (1 to: 5), ומערך דינמי שכל איבריו כתובים כביטויי Self-Evaluating כמו {3@4 . 4.5}.
  • לא: עצם רגיל ('an Object') או הביטוי {3@4 . 4+5} שמדפיס {3@4 . 9} (הביטוי 4+5 חושב ל-9).
  • קדימות: ללא סוגריים, 3 @ 4 printString מתפרש כ-3 @ ('4') כי אונרי קודם לבינארי!

2. זהות (==), שוויון (=), חוזה ה-hash ובדיקות שייכות למחלקה

השוואת כתובות זיכרון מול תוכן לוגי, והבדלי isMemberOf: מול isKindOf:.

זהות מול שוויון וחוזה הגיבוב
Object >> = anObject
    ^self == anObject

Point >> = aPoint
    self species = aPoint species
        ifTrue: [^x = aPoint x and: [y = aPoint y]]
        ifFalse: [^false]

חוזה ה-hash: אם דורסים את =, חובה לדרוס גם את hash כך שלכל שני עצמים שווים (a = b) יוחזר אותו ערך hash, אחרת חיפושם ב-Set או ב-Dictionary ייכשל!

בדיקות שייכות למחלקה

• 4 class $\to$ מחזיר SmallInteger.
• 4 isMemberOf: SmallInteger $\to$ true, אך 4 isMemberOf: Number $\to$ false (בודקת מופע ישיר בלבד, ולמחלקה מופשטת כמו Number אין מופעים ישירים!).
• 4 isKindOf: Number $\to$ true (בודקת את המחלקה או כל תת-מחלקה שלה).
• 4 respondsTo: #+ $\to$ true (מקבלת סימבול ובודקת אם העצם מבין את ההודעה).

3. שלוש רמות השכפול (shallowCopy, copyTwoLevel, deepCopy) וטיפול בשגיאות

העתקת מצביעים מול שכפול מבנים מקוננים, אתחול ב-initialize ומתודות חריגים.

אתחול ושגיאות: בעת MyClass new מופעלת אוטומטית initialize (שבה מומלץ לקרוא ל-super initialize). מתודות שגיאה וניפוי ב-Object: halt (פתיחת Debugger), assert: aBlock (בדיקת תנאי בחוזה), error: aString, deprecated: (כמו ב-doIfNotNil: המעבירה ל-ifNotNilDo:), subclassResponsibility (מתודה מופשטת), ו-shouldNotImplement (חסימת מתודה שנורשה).

6.2 היררכיית המספרים (Magnitude → Number), כפייה אוטומטית, תווים, מחרוזות וסימבולים

כיצד ממומשת מתמטיקה מונחית עצמים טהורה ללא טיפוסים פרימיטיביים: מתבנית Template Method במחלקה Magnitude, דרך שברים מדויקים (Fraction), שלמים בגודל בלתי מוגבל וכפייה מספרית אוטומטית (adaptToNumber:andSend:), ועד להבדל המהותי בזיכרון בין ByteString המוטבילית לבין Symbol הנצחי והייחודי.

🧠

מודל מנטלי ועיקרון מנחה: דיוק מתמטי, כפייה דו-שלבית וייחודיות סימבולים

1. Magnitude כתבנית השוואה

כל עצם שיש לו סדר ליניארי (מספר, תו, תאריך, זמן) יורש מ-Magnitude. תת-המחלקה מממשת רק < ו-=, ומקבלת בחינם את <=, >, >=, min:, max: ו-between:and:!

2. חישוב מדויק וכפייה אוטומטית

חילוק שלמים ב-/ אינו מאבד דיוק אלא יוצר אובייקט שבר מצומצם Fraction (6/8 ➔ 3/4). בחישוב מעורב (2 + (3/4)) מופעל מנגנון Double Dispatch דרך adaptToNumber:andSend:.

3. ByteString מול Symbol

ByteString היא מוטבילית ושתי מחרוזות זהות יכולות להיות מופעים נפרדים ('a' copy == 'a' copy ➔ false). לעומתה, Symbol הוא Immutable ומובטח שלכל רצף תווים קיים מופע יחיד בזיכרון (==)!

1. המחלקה המופשטת Magnitude ועץ המספרים Number

אופרטורי השוואה, שלושת אופרטורי החילוק (/, //, \\), Fraction, Float ומעבר שקוף בין מחלקות Integer

עץ המספרים
מעבדת חילוק

המחלקה המופשטת Magnitude (בקטגוריה Kernel-Numbers) מייצגת עצמים בעלי סדר השוואתי ליניארי (כגון Number, Character, Date, Time). האופרטורים < ו-= מוגדרים בה כמתודות מופשטות (self subclassResponsibility), ועל בסיסם מממשת Magnitude את כל שאר פעולות ההשוואה: <=, >, >=, min:, max: ו-between:and:.

תת-המחלקה המופשטת Number יורשת מ-Magnitude ומוסיפה את האופרטורים האריתמטיים +, -, *, / (ארבעתם מוגדרים ב-Number כמתודות מופשטות!), את אופרטורי השלמים // ו-\\, את אופרטור יצירת הנקודה @ (המוגדר ב-Number >> @ y ומחזיר Point x: self y: y), מתודות המרה (asFloat, asInteger, asFraction), פונקציות מתמטיות (sin, log, sqrt, squared, raiseTo:, abs) ומתודות בדיקה (even, odd, positive, negative, isZero).

מייצגת מספרים ממשיים בקירוב נקודה צפה (Double Precision). מתודות המחלקה שלה מחזירות קבועים מתמטיים כגון Float pi ו-Float e.

שומרת שני משתני מופע שלמים: numerator (מונה) ו-denominator (מכנה). נוצרת ע"י Fraction numerator: 3 denominator: 4 או אוטומטית בחילוק / בין שלמים שאינו מתחלק ללא שארית! השבר נשמר תמיד בצורה מצומצמת (בעזרת gcd:): 6/8 ➔ (3/4), 8/6 ➔ (4/3), ואילו 8/4 ➔ 2 (SmallInteger).

🔠 המחלקה Character (יורשת מ-Magnitude)

מייצגת תו בודד ונכתבת עם הקידומת $ (למשל $a, $7, $@). תווים שאינם דפיסים נוצרים באמצעות מתודות מחלקה: Character space, Character cr, Character tab, Character backspace, Character escape. מתודת המחלקה Character value: anInteger מקבלת קוד ASCII/Unicode ומחזירה את התו המתאים (למשל Character value: 65 ➔ $A), והמתודה asciiValue מחזירה את המספר השלם. משתנה המחלקה CharacterTable שומר את מערך 256 תווי ה-ASCII. מתודות בדיקה: isAlphaNumeric, isDigit, isLetter, isLowercase, isUppercase, isVowel, ו-asString.

💎 String (ByteString) לעומת Symbol

המחלקה המופשטת String יורשת מ-ArrayedCollection (אוסף תווים נגיש לפי אינדקס מ-1). יש לה שתי תתי-מחלקות מרכזיות:

  • ByteString (מחרוזת רגילה 'hello'): ניתנת לשינוי (Mutable) באמצעות at:put: (s1 at: 1 put: $H). שתי מחרוזות שוות בערכן (s1 = s2 ➔ true) יכולות להיות שני עצמים נפרדים בזיכרון (s1 == s2 ➔ false).
  • Symbol (סימבול #hello): יורשת מ-String אך היא בלתי-ניתנת לשינוי (Immutable), ומובטח שלכל רצף תווים קיים מופע יחיד בלבד בזיכרון (#hello == 'hello' asSymbol ➔ true תמיד!).

6.2 היררכיית המספרים (Magnitude → Number), תווים, מחרוזות וסימבולים

ב-Smalltalk גם מספרים, תווים ומחרוזות הם עצמים מלאים: החל ממתודות ההשוואה ב-Magnitude, דרך שברים מדויקים (Fraction) וכפייה מספרית אוטומטית, ועד להבחנה בין ByteString ל-Symbol.

1. היררכיית Magnitude → Number, שברים מדויקים וכפייה אוטומטית

מתודות מופשטות ב-Magnitude ו-Number, שלושת אופרטורי החילוק ו-adaptToNumber:andSend:.

עץ הירושה ואופרטורי החילוק

• Magnitude (מופשטת): מגדירה את < ו-= כמופשטות, ומממשת באמצעותן את <=, >, >=, min:, max:, between:and:.
• Number (מופשטת): מוסיפה את +, -, *, / כמופשטות, ואת // (מנה שלמה מעוגלת מטה), \\ (שארית) ו-@ (יצירת Point).
• תתי-המחלקות: Float (נקודה צפה), Fraction (מונה ומכנה מצומצמים: 6/8 ➔ (3/4)), ו-Integer המתחלקת ל-SmallInteger (מיוצג ישירות ב-VM), LargePositiveInteger ו-LargeNegativeInteger.

כפייה מספרית (adaptToNumber:andSend:)

כאשר מבצעים פעולה בין שני טיפוסי מספרים שונים (כגון 2 + (3/4)), המתודה SmallInteger >> + מזהה שהארגומנט אינו SmallInteger ושולחת לארגומנט (3/4) את ההודעה adaptToNumber: 2 andSend: #+ (או adaptToInteger:andSend:), הממירה את 2 לשבר ומחשבת (11/4).
מלכודת בחינה: בביטוי 15 / Integer, המספר 15 שולח ל-Integer את adaptToNumber:andSend:, ונוצרת שגיאת MessageNotUnderstood כי עצם המחלקה Integer אינו מספר!

כיצד מעל 90 מחלקות אוספים ב-Squeak מתאחדות תחת מחלקת-העל המופשטת Collection: שלוש מתודות הליבה המופשטות (add:, remove:ifAbsent:, do:), ששת הפרוטוקולים המשותפים, סיווג אוספים לפי 8 מאפיינים התנהגותיים, וניתוח 5 טכניקות המימוש הפיזיות בזיכרון.

🧠

מודל מנטלי ועיקרון מנחה: 3 מתודות מופשטות שמניעות ספריית אוספים שלמה!

אחת הדוגמאות היפות ביותר לתכנון מונחה עצמים ב-Smalltalk היא המחלקה המופשטת Collection. במקום לממש מחדש את size, isEmpty, includes:, collect:, select: ו-inject:into: בכל אחד מ-90 סוגי האוספים, Collection מממשת את כולם כבר במחלקת-העל על בסיס שלוש מתודות מופשטות בלבד (add:, remove:ifAbsent:, do:)!

1. שלושת הענפים הראשיים

תחת Collection מתפצלים 3 ענפים: SequenceableCollection (אוספים בעלי סדר ואינדקס מ-1), Set (ללא סדר וללא כפילויות, שממנו יורש גם Dictionary), ו-Bag (ללא סדר ועם כפילויות).

2. סיווג פונקציונלי (8 מאפיינים)

אנו בוחרים אוסף לפי 8 תכונות התנהגותיות: סדר (Sequenceable), מיון (Sortable), גישה באינדקס (Indexable) או במפתח (Keyed), מוטביליות (Mutable), גדילה (Growable), כפילויות, והטרוגניות.

3. מימוש בזיכרון (5 ארכיטקטורות)

מאחורי הממשק האחיד מסתתרים 5 מימושים פיזיים שונים בזיכרון: מערך קבוע, מערך פנימי מתרחב עם firstIndex/lastIndex, טבלת גיבוב (ומילון מונים ב-Bag), רשימה מקושרת, ו-3 שלמים ב-Interval.

1. עץ הירושה של Collection, 3 המתודות המופשטות ו-6 הפרוטוקולים המשותפים

מדוע Collection ומתודות הליבה שלה מופיעות בכתב נטוי (Italics), ואילו פרוטוקולים משותפים לכל האוספים

סייר פרוטוקולים

בדיאגרמות מחלקות (UML) וב-System Browser של Squeak, שם המחלקה Collection ושלוש מתודות הליבה שלה — add: newObject, remove: oldObject ifAbsent: anExceptionBlock, ו-do: aBlock — מופיעים בגופן נטוי (Italics). הסיבה לכך (שאלת מבחן מרכזית!) היא ששלוש מתודות אלו הן מתודות מופשטות שגופן ב-Collection הוא self subclassResponsibility, ולכן המחלקה Collection עצמה היא מחלקה מופשטת שלא ניתן ליצור ממנה מופעים ישירים. לעומת זאת, במחלקות הקונקרטיות Set, Bag ו-OrderedCollection, שלוש מתודות אלו מופיעות בגופן רגיל (לא נטוי) משום שכל תת-מחלקה קונקרטית דורסת ומממשת אותן בהתאם למבנה הנתונים הפנימי שלה!

1 Sequenceable איברים המסודרים ברצף מוגדר מהאיבר הראשון (first) ועד האחרון (last). ✅ כל תתי-המחלקות של SequenceableCollection (Array, OrderedCollection, Interval, LinkedList, String).

2 Sortable האיברים נשמרים ממוינים אוטומטית על פי תכונה או קריטריון השוואה (<= או sortBlock:). ✅ SortedCollection.
❌ שאר האוספים.
3 Indexable גישה לאיברים באמצעות אינדקס מספרי שלם מ-1 ועד size (at: ו-at:put:). ✅ Array, OrderedCollection, String, Interval (קריאה בלבד ב-at:).
❌ Set, Bag (at: זורקת שגיאה!).
4 Keyed גישה לאיברים באמצעות מפתחות שרירותיים (at: key, at: key put: value) במקום אינדקס מספרי. ✅ Dictionary ותתי-המחלקות שלו (IdentityDictionary).
5 Mutable ניתן לשנות את תוכן האוסף לאחר שנוצר (הצבת איברים ב-at:put: או הוספה/מחיקה). ✅ רוב האוספים (Array, OrderedCollection, Set, Bag, ByteString).
❌ Immutable: Interval ו-Symbol.
6 Growable האוסף יכול לגדול ולהתכווץ דינמית במהלך חייו (add:, addFirst:, addLast:, remove:). ✅ OrderedCollection, SortedCollection, Set, Bag, Dictionary, LinkedList.
❌ גודל קבוע: Array, String, Interval (add: אסורה!).
7 Accepts duplicates האוסף מסוגל להחזיק מספר עותקים שווים של אותו איבר. ✅ Bag, Array, OrderedCollection, SortedCollection.
❌ מנפים כפילויות: Set וכן מפתחות ב-Dictionary.
8 Heterogeneous יכול להכיל איברים מטיפוסים/מחלקות שונות באותו אוסף, לעומת אוסף הומוגני המוגבל לטיפוס יחיד. ✅ הטרוגניים: Array, OrderedCollection, Set, Bag, Dictionary.
❌ הומוגניים: String / Symbol (רק Character!), ByteArray, IntegerArray, FloatArray, Interval.

5 Memory Architectures
1. מימושי מערך (Arrayed)

במחלקות Array ו-String, האיברים נשמרים ישירות בתוך שדות אינדקסליים של עצם האוסף עצמו (ללא מערך עזר חיצוני). לכן גודלם קבוע ומוקצה בעת היצירה, והגישה לפי אינדקס (at:) מתבצעת ב-$O(1)$.

2. מימושים סדורים (Ordered)

ב-OrderedCollection ו-SortedCollection, האיברים נשמרים בתוך מערך פנימי המוחזק במשתנה המופע array, לצד שני מצביעי גבולות: firstIndex ו-lastIndex. כאשר המערך הפנימי מתמלא, מוקצה אוטומטית מערך חדש וגדול יותר!

3. מימושי גיבוב (Hashed) ומימוש Bag

Set ו-Dictionary מחזיקים מערך פנימי המשמש כטבלת גיבוב (Hash Table). לעומתם, Bag ממומשת באמצעות משתנה מופע contents מסוג Dictionary שבו כל איבר ייחודי הוא המפתח (Key) ומספר המופעים שלו באוסף הוא הערך (Value)!

4. מימושים מקושרים (Linked)

LinkedList ממומשת כרשימה מקושרת סטנדרטית המחזיקה מצביעים לחוליה הראשונה (firstLink) ולאחרונה (lastLink), ומאפשרת הוספה והסרה בקצוות ב-$O(1)$.

5. מימושי אינטרוול (Interval) – חיסכון זיכרון של $O(1)$

מופע של Interval (כגון 1 to: 1000000 by: 2) שומר שלושה משתני מופע שלמים בלבד: ערך ההתחלה (start = 1), ערך הסיום (stop = 1000000) וגודל הצעד (step = 2), ומחשב כל איבר לפי נוסחת סדרה חשבונית: $\text{start} + (i - 1) \times \text{step}$.

3 ענפי הירושה תחת Collection

1. SequenceableCollection: אוספים סדורים בעלי first, last ואינדקס מ-1 (ArrayedCollection → Array / String, OrderedCollection → SortedCollection, Interval, LinkedList).
2. Set: ללא סדר וללא כפילויות (יורשים ממנה: IdentitySet ו-Dictionary → IdentityDictionary).
3. Bag: ללא סדר ועם כפילויות (יורשת ממנה: IdentityBag).

8 המאפיינים הפונקציונליים

(1) Sequenceable (רצף סדור); (2) Sortable (SortedCollection); (3) Indexable (גישה ב-at: לפי אינדקס מ-1); (4) Keyed (גישה לפי מפתח ב-Dictionary); (5) Mutable מול Immutable (Interval ו-Symbol הם Immutable!); (6) Growable מול גודל קבוע (Array ו-Interval קבועים בגודלם); (7) Accepts duplicates (Set ו-Dictionary מנפים מפתחות כפולים); (8) Heterogeneous מול הומוגני (String לתווים בלבד).

2. חמש טכניקות המימוש בזיכרון

ייצוג פיזי של האוספים בזיכרון המחשב.

• מימושי מערך (Array, String): האיברים נשמרים ישירות בשדות המופע בגודל קבוע.
• מימושים סדורים (OrderedCollection, SortedCollection): משתנה מופע array (המוקצה מחדש כשמתמלא) + שני אינדקסים firstIndex ו-lastIndex.
• מימושי גיבוב (Set, Dictionary, Bag): טבלת גיבוב במערך פנימי; Bag שומר Dictionary פנימי (איבר $\to$ מונה מופעים).

• מימושים מקושרים (LinkedList): שרשרת חוליות מקושרות.
• מימושי אינטרוול (Interval): שומר 3 מספרים שלמים בלבד (start, stop, step) בסיבוכיות מקום $O(1)$!

1. אינדקס מ-1 וליטרל מול דינמי

בכל אוסף אינדקסלי ב-Smalltalk האינדקס הראשון הוא 1 (ולא 0!). במערך ליטרלי #(1+2) התוכן מפוענח בזמן הידור ל-3 אסימונים #(1 #+ 2), ואילו במערך דינמי {1+2} הביטויים מחושבים בזמן ריצה ל-#(3).

2. Set / Bag / Dictionary (לפי =)

משווים איברים ומפתחות לפי שוויון לוגי (=) ו-hash. לכן 3 ו-9/3 או שתי מחרוזות נפרדות 'ab' copy ו-'ab' copy נחשבים בהם לאותו איבר בדיוק!

3. IdentitySet / Bag / Dict (לפי ==)

משווים לפי זהות מצביעים בזיכרון (==) ו-identityHash. לכן שני מופעים נפרדים 3@4 ו-3@4 או שתי מחרוזות 'ab' copy נשמרים בהם כשני איברים נפרדים!

1. אוספים סדורים: Array, OrderedCollection, Interval ו-SortedCollection

שלוש דרכי היצירה של מערך, פעולות הוספה והסרה גמישות, תחומי מספרים, ומיון עם sortBlock:

#(...) מול {...}
מעבדת מחלקות

1. המחלקה Array (מערך בגודל קבוע, אינדקס ראשון 1)

מערך הוא אוסף הטרוגני בגודל קבוע שניתן לגשת לאיבריו ולשנותם באמצעות at: ו-at:put: (האינדקס הראשון הוא תמיד 1!). ניסיון לשלוח add: או remove: למערך זורק shouldNotImplement. קיימות שלוש דרכים ליצירת מערך: 

"א. מתודות המחלקה new: ו-with: :"
Array new: 5.                         "-> #(nil nil nil nil nil)"
Array with: 1 with: 2/3 with: 'xxx'.  "-> {1 . (2/3) . 'xxx'}"

"ב. מערך ליטרלי #(...) - מפוענח בזמן הידור ללא חישוב הודעות!"
#(10 'hello' true nil).               "-> 4 איברים"
#(1 + 2).                             "-> #(1 #+ 2) (3 איברים: 1, הסימבול #+, ו-2!)"
#(10@10 100@100).                     "-> #(10 #@ 10 100 #@ 100) (6 איברים!)"

"ג. מערך דינמי {...} - ביטויים מופרדים בנקודות המחושבים בזמן ריצה:"
{1 + 2}.                              "-> #(3) (איבר אחד!)"
{1/2 . 10 atRandom . 'hello ' , 'world'}. "-> {(1/2) . 7 . 'hello world'}"

2. המחלקה OrderedCollection (רשימה דינמית מתרחבת)

כללית וגמישה יותר ממערך: שומרת על סדר הכנסת האיברים ויכולה לגדול ולהתכווץ דינמית. תומכת ב-add: (מוסיפה בסוף, כמו addLast:), addFirst: (מוסיפה בהתחלה), insert:before:, at:, at:put: (רק לאינדקסים שכבר קיימים בין 1 ל-size!), remove: (מסירה את המופע הראשון שמתאים, או זורקת חריג אם אינו קיים), ו-remove:ifAbsent:: 

ordCol := OrderedCollection new.
ordCol add: 'xx'; add: 'yy'; addFirst: 'zz'.
ordCol.               "-> an OrderedCollection('zz' 'xx' 'yy')"
ordCol add: 'zz'.     "-> an OrderedCollection('zz' 'xx' 'yy' 'zz')"
ordCol remove: 'zz'.  "-> an OrderedCollection('xx' 'yy' 'zz') (הסיר את הראשון!)"

3. המחלקה Interval (תחום מספרים – סדרה חשבונית)

מייצגת סדרה חשבונית של מספרים (כולל הקצוות – Inclusive) באמצעות 3 מספרים בלבד (start, stop, step). היא תומכת ב-at: ובאיטרטורים, אך היא Immutable (שליחת at:put: או add: אסורה!): 

"יצירה באמצעות מתודות המחלקה של Interval:"
Interval from: 1 to: 100.        "-> (1 to: 100)"
Interval from: 1 to: 10 by: 2.   "-> (1 to: 10 by: 2) איברים: 1,3,5,7,9"

"יצירה באמצעות הודעות to: ו-to:by: הנשלחות לעצם מסוג Number:"
10 to: 20 by: 2.                 "-> (10 to: 20 by: 2)"
1 to: 10 by: 1/2.                "-> (1 to: 10 by: (1/2))"

4. המחלקה SortedCollection (אוסף ממוין אוטומטית)

יורשת מ-OrderedCollection ושומרת את איבריה ממוינים בכל הוספה (add:). כברירת מחדל המיון מתבצע באמצעות ההודעה <= (הנתמכת ב-Magnitude, String, Point). כאשר רוצים למיין עצמים שאינם תומכים ב-<= (כמו Rectangle) או למיין לפי סדר מותאם אישית, מספקים בלוק מיון בן 2 פרמטרים (sortBlock:): 

"מיון ברירת מחדל (לפי <=) - שימו לב לשימוש ב-yourself!"
SortedCollection new add: 5; add: 3; add: 2/4; add: 3; yourself.
"-> a SortedCollection((1/2) 3 3 5)"

"מיון מותאם אישית של מלבנים לפי שטחם באמצעות sortBlock: :"
shapes := SortedCollection sortBlock: [:s1 :s2 | s1 area <= s2 area].
shapes addAll: {
    Rectangle origin: 0@0 corner: 10@20.
    Rectangle origin: 0@0 corner: 12@12.
    Rectangle origin: 0@0 corner: 10@10
}.

2. מילונים (Dictionary ו-Association) וקבוצות (Set)

זוגות מפתח-ערך (key->value), newFrom: מול withAll:, פעולות קבוצות (union:, intersection:) ומדוע Set >> asSet מחזירה ^self

🗂️ המחלקה Dictionary (יורשת מ-Set!)

מילון הוא אוסף של זוגות מפתח-ערך המיוצגים כמופעים של המחלקה Association (נוצרים ע"י האופרטור הבינארי ->, למשל #Uri -> aDate). מתודות מרכזיות: at: key put: val (מוסיפה או מעדכנת ערך למפתח), at: key (מחזירה את הערך או זורקת KeyNotFound אם אינו קיים), at: key ifAbsent: aBlock, removeKey: key, keys (מחזירה Set של המפתחות), values (מחזירה Array של הערכים), ו-associations (מערך הזוגות). 

"יצירה מפורשת עם מערך אסוציאציות (newFrom:):"
dic1 := Dictionary newFrom: {#one->1 . #two->2 . #three->3}.
dic1 keys.          "-> a Set(#two #three #one)"
dic1 values.        "-> #(2 3 1)"

"יצירה ממערך ערכים בלבד (withAll:) - מצמידה מפתחות סידוריים 1..N!"
dic2 := Dictionary withAll: #(7 3 1 3).
dic2 associations.  "-> {1->7 . 2->3 . 3->1 . 4->3}"

⭕ המחלקה Set (קבוצה ללא סדר וללא כפילויות)

קבוצה מנפה כפילויות אוטומטית על פי שוויון ערכי (=) ו-hash. לא ניתן לשלוף איברים מקבוצה באמצעות at: (שליחת at: ל-Set זורקת שגיאה!). מתודות מרכזיות: add:, includes:, union: aSet (מחזירה קבוצת איחוד חדשה ללא שינוי המקבל!), ו-intersection: aSet (מחזירה קבוצת חיתוך חדשה): 

s := Set new.
s add: 3; add: 9/3; add: 2.
s size.   "-> 2 (כי 3 = (9/3) ולכן נשמר עותק אחד בלבד!)"

s2 := Set newFrom: #(1 2 2 3 4 1).  "-> a Set(1 2 3 4) (size = 4)"
(Set newFrom: #(0 2 4)) union: (Set newFrom: #(1 2 3)).        "-> a Set(0 1 2 3 4)"
(Set newFrom: #(0 2 4)) intersection: (Set newFrom: #(1 2 3)). "-> a Set(2)"

דגש מבחן (מועד 2015א): מדוע קיימת המתודה Set >> asSet ^self? ב-Collection המתודה asSet יוצרת קבוצה חדשה ומעתיקה אליה את כל האיברים. הדריסה ב-Set מחזירה ^self כדי לאפשר פולימורפיזם שקוף (קוד שמקבל אוסף כלשהו ושולח לו asSet יפעל ביעילות $O(1)$ ללא הקצאת זיכרון מיותרת אם האוסף כבר מסוג Set!).

3. ההבחנה הקריטית למבחנים: Set / Bag / Dictionary מול IdentitySet / IdentityBag / IdentityDictionary

השוואה לפי = ו-hash לעומת השוואה לפי == ו-identityHash, ותבנית ה-Factory Method ב-Bag class >> contentsClass

Bag מול IdentityBag

במערכת Smalltalk לכל אחד משלושת אוספי הגיבוב (Set, Bag, Dictionary) קיימת תת-מחלקה מקבילה המתחילה במילה Identity: בעוד ש-Set, Bag ו-Dictionary מאתרים ומשווים איברים או מפתחות באמצעות שוויון לוגי (=) ופונקציית הגיבוב hash, הרי ש-IdentitySet, IdentityBag ו-IdentityDictionary משווים איברים או מפתחות באמצעות זהות מצביעים בזיכרון (==) ו-identityHash!

תבנית העיצוב Factory Method באוספים

Bag vs IdentityBag
מתי Bag ו-IdentityBag על אותו מערך קלט יהיו שווים (b = d ➔ true)?

כאשר כל האיברים השווים בערכם במערך הקלט startArray הם גם אותו עצם פיזי בזיכרון (==)! למשל: מערך של סימבולים או מספרים שלמים קטנים (SmallInteger) כמו startArray := #(#a #a #b) או #(1 2 1), או כאשר שומרים משתנה p := 3@4 ומכניסים את אותו מופע פעמיים: {p . p}.

מתי Bag ו-IdentityBag על אותו מערך קלט לא יהיו שווים (b = d ➔ false)?

כאשר המערך מכיל שני מופעים נפרדים בזיכרון (~~) שערכם הלוגי שווה (=), או שני עצמים מטיפוסים שונים שווים בערכם! למשל: startArray := {3@4 . 3@4}, או {'hello' copy . 'hello' copy}, או {'abc' . #abc} (כי ב-Smalltalk מחרוזת וסימבול בעלי אותם תווים מקיימים 'abc' = #abc ➔ true אך 'abc' == #abc ➔ false!).

🎯 מלכודות #(10@10 100@100), השוואת משולשים ב-Set מול Bag, Heap ומערך מוגבל-טיפוס (MyArrayClass)

1. מלכודת מערך ליטרלי: b := #(10@10 100@100). b size ➔ 6!

מערך ליטרלי #(...) מפוענח בזמן הידור כאוסף אסימונים סטטיים המופרדים ברווח ללא שליחת הודעות כלל! לכן האופרטור @ אינו מופעל אלא נשמר כסימבול #@:

[1] 10
[2] #@
[3] 10
[4] 100
[5] #@
[6] 100

לעומת זאת, במערך דינמי {10@10 . 100@100} size ➔ 2, ובבדיקה {1+3} = #(1+3) מוחזר false (כי #(4) ~= #(1 #+ 3))!

2. מלכודת השוואת משולשים: מדוע Set כושל ו-Bag מצליח?

נניח שרוצים לבדוק אם לשני משולשים יש אותן 3 צלעות (בסדר כלשהו). אם נכניס את 3 הצלעות של כל משולש ל-Set ונבדוק setA = setB:

Triangle 1: (4, 3, 3)
Set: a Set(3 4)
Bag: {3->2, 4->1}
Triangle 2: (4, 4, 3)
Set: a Set(3 4) (Equal!)
Bag: {3->1, 4->2}

המסקנה למבחן: Set בולע כפילויות ולכן מחזיר שמשולש (4,3,3) שווה למשולש (4,4,3)! הפתרון הנכון הוא להשתמש ב-Bag השומר את מספר המופעים של כל צלע.

3. ערימה ממוינת (Heap) ומיון מותאם (sortModulu10)

המחלקה Heap (ועמה SortedCollection) מחייבת שאיבריה יהיו ברי-השוואה זה לזה: הרצת h := Heap new. h add: 3; add: 5; add: '4' תזרוק שגיאה בעת ניסיון השוואת המחרוזת '4' למספר! למיון מותאם של כל אוסף (למשל לפי שארית בחלוקה ב-10) נגדיר ב-Collection:

Collection >> sortModulu: aNumber
    ^self sorted: [:x :y |
        (x isNumber & y isNumber)
            ifTrue: [(x \ aNumber) < (y \ aNumber)]
            ifFalse: [self error: 'cannot sort non-numbers']]
4. מערך מוגבל-טיפוס (MyArrayClass) ו-CollectionInspector

כדי ליצור תת-מחלקה של Array האוכפת שכל איבר שמוכנס ב-at:put: יהיה מופע של classForObjects (או תת-מחלקה שלה, או nil):

Array variableSubclass: #MyArrayClass
    instanceVariableNames: 'classForObjects' ...

MyArrayClass >> at: index put: anObject
    (classForObjects isNil or: [anObject isNil]
        or: [anObject isKindOf: classForObjects])
            ifTrue: [^super at: index put: anObject].
    self error: 'Invalid element type!'

דגש חשוב: גם כאשר פותחים b inspect (CollectionInspector) ומשנים איבר ידנית בחלון ה-Inspector, ה-Inspector מעדכן את השדה על ידי שליחת at:put: ולכן ההגבלה נאכפת אוטומטית!

6.4 מחלקות האוספים העיקריות ו-Set / Bag / Dictionary מול Identity

הכרת המחלקות המרכזיות בספריית האוספים וההבחנה בין השוואה לוגית (= ו-hash) להשוואת זהות (== ו-identityHash).

1. אוספים סדורים: Array, OrderedCollection, Interval ו-SortedCollection

אינדקס ראשון 1, מערך ליטרלי מול דינמי, רשימה דינמית ומיון עם sortBlock:.

Array ו-OrderedCollection

• Array: גודל קבוע, אינדקס מ-1 (at: / at:put:). ליטרלי בזמן הידור: #(1+2) ➔ #(1 #+ 2) (גודל 3); דינמי בזמן ריצה: {1+2} ➔ #(3) (גודל 1).
• OrderedCollection: גדלה דינמית. תומכת ב-add:, addFirst:, addLast:, insert:before:, remove:, remove:ifAbsent:.

Interval ו-SortedCollection

• Interval: תחום מספרים (1 to: 10 by: 2 או Interval from: 1 to: 10 by: 2). הוא Immutable (at:put: אסור).
• SortedCollection: ממיינת אוטומטית לפי <= או לפי בלוק מותאם SortedCollection sortBlock: [:a :b | a area <= b area].

2. Set, Bag ו-Dictionary מול משפחת Identity

מילונים, קבוצות, ותבנית contentsClass ב-Bag מול IdentityBag.

Dictionary ו-Set

• Dictionary: שומר זוגות Association (#key -> value). מתודות: at:put:, at:ifAbsent:, keys (Set), values (Array), associations. Dictionary withAll: #(7 3) מצמיד מפתחות 1->7, 2->3.
• Set: ללא סדר וללא כפילויות (union:, intersection:, includes:; אין at:!).

השוואת = מול == (Identity)

• Set / Bag / Dictionary משווים לפי = ו-hash.
• IdentitySet / IdentityBag / IdentityDictionary משווים לפי == ו-identityHash.
• Bag שומר מילון פנימי שסוגו נקבע ע"י Bag class >> contentsClass ^Dictionary, ואילו IdentityBag class >> contentsClass ^IdentityDictionary!

6.4 סיכום מהיר: מחלקות אוספים עיקריות ומשפחת Identity

1. Array:
• אינדקס מ-1. גודל קבוע.
• #(1+2) ➔ #(1 #+ 2) (הידור).
• {1+2} ➔ #(3) (ריצה).
2. Ordered & Sorted:
• OrderedCollection: addFirst:, addLast:, remove:ifAbsent:.
• SortedCollection: <= או sortBlock: [:a :b | ...].
3. Dictionary & Set:
• Dictionary: זוגות key->val; keys (Set), values (Array).
• Set: ללא at:; union:, intersection:; asSet ^self.
4. רגיל מול Identity:
• Set/Bag/Dict: לפי = ו-hash.
• Identity*: לפי == ו-identityHash (contentsClass ב-Bag).
📦 דגשי מערכים, מילונים והשוואת משולשים

• ליטרל מול דינמי: #(10@10 100@100) size = 6 לעומת {10@10 . 100@100} size = 2, ו-{1+3} = #(1+3) הוא false.
• משולשים ורב-קבוצות: השוואת צלעות משולשים (4,3,3) מול (4,4,3) חייבת להתבצע עם Bag ולא Set!
• מילון: Dictionary newFrom: {1->#a} מצפה לאוסף Association, בעוד Dictionary withAll: #(7 3) ממפה אינדקסים 1->7, 2->3.

⚖️ תבנית ה-Factory Method ב-Bag מול IdentityBag

• Bag class >> contentsClass ^Dictionary (משווה לפי = ו-hash).
• IdentityBag class >> contentsClass ^IdentityDictionary (משווה לפי == ו-identityHash).
• עבור {3@4 . 3@4}: ב-Bag מפתח אחד עם מונה 2; ב-IdentityBag שני מפתחות נפרדים עם מונה 1.

6.5 איטרטורים פונקציונליים ומימושם במחלקה Collection: do:, collect:, select:, reject:, detect:ifNone: ו-inject:into:

ניתוח קוד המימוש האמיתי של כל האיטרטורים במחלקה Collection: כיצד do: ממומש ב-SequenceableCollection, ב-Set וב-Bag, מדוע collect: ו-select: משתמשים ב-self species new, כיצד detect:ifNone: מבצע יציאה לא-מקומית (^each), ומעקבי טבלה מלאים של inject:into:.

🧠

מודל מנטלי ועיקרון מנחה: פירמידת האנומרציה מעל do: ו-self species

1. הכל נשען על do:

כל תת-מחלקה קונקרטית של Collection מממשת את do: aBlock לפי המבנה הפנימי שלה. כל שאר האיטרטורים (collect:, select:, detect:ifNone:, inject:into:) כתובים פעם אחת ב-Collection באמצעות שליחת self do: [...]!

2. תפקיד self species new

ב-collect: וב-select: יוצרים את אוסף התוצאה ע"י self species new (ולא self class new!) כי אוספים מוגבלים כמו Interval אינם יכולים להחזיק תוצאות שרירותיות, ולכן Interval >> species מחזירה Array!

3. קיפול משמאל ב-inject:into:

האיטרטור inject: thisValue into: [:acc :each | ...] מאתחל את הצובר ל-thisValue ובכל צעד מציב בצובר את ערך הבלוק. הוא מאפשר לממש סכימה, מכפלה, מקסימום, מנייה ואפילו בניית מבנים מקוננים!

1. איטרציית הבסיס (do:), מימושה במחלקות השונות ואיטרטורי Dictionary

איך עובדת do: ב-SequenceableCollection, ב-Set וב-Bag, ומה עושה do: על מילון?

דקויות איטרציה

המתודה do: aBlock מקבלת בלוק בעל פרמטר אחד ומעריכה אותו עבור כל איבר באוסף. מכיוון ש-Collection >> do: היא מופשטת (self subclassResponsibility), כל ענף בהיררכיה מממש אותה לפי ייצוגו הפנימי בזיכרון (שאלת מבחן 2020ב!):

1. ב-SequenceableCollection

עוברת בלולאת to:do: על כל האינדקסים מ-1 ועד self size ושולפת כל איבר באמצעות self at: index: 

SequenceableCollection >> do: aBlock
    1 to: self size do:
        [:index | aBlock value: (self at: index)]

2. ב-Set (טבלת גיבוב)

סורקת את תאי המערך הפנימי (array) של טבלת הגיבוב, ומפעילה את aBlock רק על התאים שאינם ריקים (notNil): 

Set >> do: aBlock
    size = 0 ifTrue: [^self].
    1 to: array size do: [:index |
        | each |
        (each := array at: index) ifNotNil:
            [aBlock value: each]]

3. ב-Bag (מילון מונים פנימי)

עוברת על הזוגות במילון הפנימי contents (assoc key הוא האיבר ו-assoc value הוא המונה), ומפעילה את הבלוק timesRepeat: פעמים! 

Bag >> do: aBlock
    contents associationsDo: [:assoc |
        assoc value timesRepeat:
            [aBlock value: assoc key]]
וריאציות של do: ואיטרטורים ייעודיים של Dictionary:
  • withIndexDo: [:each :i | ...] (או doWithIndex:) — מעבירה לבלוק גם את האיבר התורן וגם את האינדקס שלו (1..size).
  • do: aBlock without: anItem ו-reverseDo: aBlock — סריקה תוך דילוג על איבר מסוים, או סריקה בסדר הפוך מהסוף להתחלה.
  • איטרציה על Dictionary: שליחת aDict do: [:v | ...] עוברת על הערכים (values) בלבד (זהה ל-valuesDo:)!
  • סריקת מפתחות וזוגות במילון: keysDo: [:k | ...], associationsDo: [:assoc | ...], ו-keysAndValuesDo: [:k :v | ...].

2. מיפוי (collect:) וסינון (select: ו-reject:) ותפקיד self species new

הקוד המדויק במחלקה Collection, מדוע משתמשים ב-species ולא ב-class, ומלכודת collect: על מחרוזת

1. איסוף ומיפוי (collect: – Map)

מעריכה את הבלוק עבור כל איבר באוסף ומחזירה אוסף חדש מאותו מין (species) המכיל את תוצאות הבלוק: 

Collection >> collect: aBlock
    | newCollection |
    newCollection := self species new.
    self do: [:each |
        newCollection add: (aBlock value: each)].
    ^newCollection

דוגמה: #('this' 'is') collect: [:e | e asUppercase] ➔ #('THIS' 'IS').

2. בחירה (select: – Filter)

מחזירה אוסף חדש מאותו species הכולל רק את האיברים שעבורם הבלוק החזיר true: 

Collection >> select: aBlock
    | newCollection |
    newCollection := self species new.
    self do: [:each |
        (aBlock value: each)
            ifTrue: [newCollection add: each]].
    ^newCollection

דוגמה: #(1 2 3 4) select: [:x | x even] ➔ #(2 4).

3. ניפוי (reject: – משלים ל-select:)

מחזירה אוסף חדש הכולל רק את האיברים שעבורם הבלוק החזיר false (ממומשת באמצעות select:!): 

Collection >> reject: aBlock
    ^self select: [:element |
        (aBlock value: element) == false]

דוגמה: #('This' 'is' 'Example') reject: [:e | (e at: 1) isLowercase] ➔ #('This' 'Example').

💡 מדוע self species new ולא self class new? (דגש מבחן!)

עבור רוב המחלקות, Object >> species מחזירה ^self class. אולם עבור מחלקות בעלות אילוץ מבני כמו Interval, ביצוע (1 to: 5) collect: [:x | x squared] מייצר את המספרים 1, 4, 9, 16, 25 שאינם סדרה חשבונית ואינם יכולים להיות מיוצגים כ-Interval! לכן Interval >> species מחזירה Array. בנוסף, SequenceableCollection דורסת את collect: ויוצרת self species new: self size עם הצבה ב-at:put: (כי Array אינו תומך ב-add:!).

⚠️ מלכודת collect: על מחרוזת (String)!

מכיוון ש-String >> species היא String (ומחרוזת היא אוסף הומוגני שיכול להכיל אך ורק איברים מסוג Character!), הביטוי 'abc' collect: [:ch | ch asUppercase] יצליח ויחזיר 'ABC', אך הביטוי 'abc' collect: [:ch | ch asciiValue] יזרוק שגיאת ריצה כשינסה להציב מספר שלם (97) לתוך מחרוזת! מעבדת איטרטורים

🔎 איתור האיבר הראשון: detect: ו-detect:ifNone:

detect: aBlock מחזירה את האיבר הראשון באוסף שעבורו aBlock מחזיר true, ואם לא נמצא איבר כזה מעוררת חריג (errorNotFound:). היא ממומשת ע"י detect: aBlock ifNone: exceptionBlock המקבלת בלוק שני ללא פרמטרים המוערך רק אם אף איבר לא התאים. שימו לב לשימוש האלגנטי ביציאה לא-מקומית (^each) מתוך הבלוק שעוצרת את לולאת do: מיד במציאת האיבר הראשון! 

Collection >> detect: aBlock
    ^self detect: aBlock ifNone: [self errorNotFound: aBlock]

Collection >> detect: aBlock ifNone: exceptionBlock
    self do: [:each | (aBlock value: each) ifTrue: [^each]].
    ^exceptionBlock value

דוגמה: #('This' 'is' 'an' 'example') detect: [:e | e size > 4] ➔ 'example'.

🧮 צבירה וקיפול משמאל: inject: thisValue into: binaryBlock

מקבלת ערך התחלתי (thisValue) ובלוק עם שני פרמטרים ([:subTotal :next | ...]). המשתנה הצובר nextValue מאותחל ל-thisValue, ובכל איטרציה של do: מקבל את הערך המוחזר מהפעלת הבלוק על הערך הצבור הקודם ועל האיבר התורן each: 

Collection >> inject: thisValue into: binaryBlock
    | nextValue |
    nextValue := thisValue.
    self do: [:each |
        nextValue := binaryBlock value: nextValue value: each].
    ^nextValue

דוגמאות: סכום (1 to: 10) inject: 0 into: [:sum :x | sum + x] ➔ 55; ומימוש occurrencesOf: anObject ב-Collection: ^self inject: 0 into: [:cnt :y | (y = anObject) ifTrue: [cnt + 1] ifFalse: [cnt]]!

🚀 מימוש endsWith:, endsWithAnyOf:, with:select: ו-occurrencesOf: בעזרת inject:into:

1. endsWith: ו-endsWithAnyOf:

ב-SequenceableCollection נבדוק אם הסיומת של self זהה ל-sequence באמצעות היסט offset := self size - sequence size, ונממש את endsWithAnyOf: בשורה אחת עם anySatisfy::

SequenceableCollection >> endsWith: sequence
    | sequenceSize offset |
    0 = (sequenceSize := sequence size) ifTrue: [^true].
    (offset := self size - sequenceSize) < 0 ifTrue: [^false].
    1 to: sequenceSize do: [:i |
        (self at: i + offset) = (sequence at: i)
            ifFalse: [^false]].
    ^true

SequenceableCollection >> endsWithAnyOf: aCollection
    ^aCollection anySatisfy: [:seq | self endsWith: seq]
2. איטרטור זוגות with:select: ומיקומו בהיררכיה

עובר במקביל על איבר ה-$i$ ב-self ואיבר ה-$i$ ב-otherCollection, ומחזיר OrderedCollection של איברי self שעבורם הבלוק הדו-ארגומנטי החזיר true. ממוקם ב-SequenceableCollection כי הוא תלוי בסדר ובאינדקסים תואמים!

SequenceableCollection >> with: otherCol select: aTwoArgBlock
    | result |
    self size = otherCol size
        ifFalse: [^self error: 'Sizes must match'].
    result := OrderedCollection new.
    1 to: self size do: [:i |
        (aTwoArgBlock value: (self at: i) value: (otherCol at: i))
            ifTrue: [result add: (self at: i)]].
    ^result
3. מימוש occurrencesOf: בעזרת inject:into:

דוגמה קלאסית ממצגות הקורס לשימוש ב-inject:into: כמונה מופעים אוניברסלי במחלקה Collection:

Collection >> occurrencesOf: anObject
    ^self inject: 0 into: [:count :each |
        (each = anObject)

6.5 איטרטורים פונקציונליים ומימושם במחלקה Collection

כל האיטרטורים ב-Collection ממומשים מעל do:. שליטה בקוד הפנימי שלהם חיונית לשאלות השלמת קוד ומעקב בבחינות.

1. קוד המימוש של do:, collect:, select: ו-reject:

סריקת איברים, יצירת אוסף תוצאה עם self species new וסינון.

do: ואיטרטורי Dictionary
SequenceableCollection >> do: aBlock
    1 to: self size do: [:index | aBlock value: (self at: index)]

Bag >> do: aBlock
    contents associationsDo: [:assoc |
        assoc value timesRepeat: [aBlock value: assoc key]]

ב-Dictionary: do: עוברת על הערכים (values)! למפתחות ולזוגות: keysDo:, associationsDo:, keysAndValuesDo:.

collect:, select: ו-reject:
Collection >> collect: aBlock
    | newCollection |
    newCollection := self species new.
    self do: [:each | newCollection add: (aBlock value: each)].
    ^newCollection

Collection >> select: aBlock
    | newCollection |
    newCollection := self species new.
    self do: [:each | (aBlock value: each) ifTrue: [newCollection add: each]].
    ^newCollection

Collection >> reject: aBlock
    ^self select: [:element | (aBlock value: element) == false]

OrderedCollection >> do: aBlock

3. סכנת שינוי איבר מוטבילי ב-Set או ב-Dictionary

עדיף להשתמש בעצמים בלתי-ניתנים לשינוי (Immutable כגון Symbol, Number) כמפתחות במילון או כאיברים ב-Set. אם מכניסים עצם מוטבילי (כגון OrderedCollection או ByteString) ל-Set, הוא ממוקם במגירה לפי ערך ה-hash שלו ברגע ההכנסה. אם לאחר מכן נשנה את תוכנו של העצם, ערך ה-hash שלו ישתנה, אך העצם יישאר במגירה הישנה — ולכן גם חיפוש העצם עצמו (set includes: obj) יחפש במגירה החדשה ויחזיר false!

4. מתי שני אוספים שווים ב-=?

ב-SequenceableCollection >> =, שני אוספים סדורים הם שווים אם ורק אם: (1) יש להם אותו species, (2) אותו אורך (size), ו-(3) אותם איברים (=) באותו סדר. לכן #(1 2 3) = (OrderedCollection with: 1 with: 2 with: 3) מחזיר false (כי Array species ~= OrderedCollection species!), בעוד ש-#(1 2 3) = (1 to: 3) עשוי להחזיר false ב-= למרות שלשניהם species == Array בגלל בדיקת hasEqualElements: או סוג המחלקה.

5. היכן למקם מתודות חדשות על אוספים במבחן?

  • אם המתודה נדרשת לפעול על כל אוסף ונשענת על do: / inject:into: / select: — ממקמים אותה ב-Collection.
  • אם המתודה תלויה בסדר האיברים או באינדקסים (למשל בדיקת פלינדרום at: i מול at: size - i + 1) — ממקמים ב-SequenceableCollection (או ArrayedCollection).

💥 כיצד שינוי מחרוזת בתוך Set יוצר קבוצה לא-חוקית עם שני איברים זהים? ('smalltalk' ➔ 'smarttalk')

שלב א': הכנסה תקינה לקבוצה
a := Set new.
b := 'smalltalk' copy.
c := 'smarttalk' copy.
a add: b; add: c.

המחרוזת b ממופה למגירה לפי 'smalltalk' hash, והמחרוזת c ממופה למגירה אחרת לפי 'smarttalk' hash. ב-a יש: a Set('smalltalk' 'smarttalk').

שלב ב': מוטציה במקום דרך מצביע חיצוני
b at: 4 put: $r;
  at: 5 put: $t.

שינינו את התו ה-4 וה-5 של b מתוך המצביע החיצוני, מבלי שהקבוצה a תדע על כך ומבלי לחשב גיבוב מחדש (Rehash)!

בעיה 1: מנגנון ההדפסה (printOn: aStream), קדימות הודעות וזיהוי Self-Evaluating

Object & Point • הדפסה ותחביר

א. במתודה Point >> printOn: aStream מופיעות השורות (y isNumber and: [y negative]) ifTrue: [aStream space] לפני הדפסת y. מדוע קיימות שורות אלו, ומה היה קורה בלעדיהן?

ב. מה יחזיר כל אחד מהביטויים הבאים, והאם הביטוי מדגים עצם שהוא Self-Evaluating?
1) (3 @ 4) printString  |  2) 3 @ 4 printString  |  3) {3@4 . 4.5}  |  4) {3@4 . 4+5}

🧭 איך לגשת לבעיה? אסטרטגיית פתרון ודגשים

יש לבדוק כיצד המהדר של Smalltalk מפענח רצף של תווים מיוחדים (כמו @ ו--) כשאינם מופרדים ברווח, ולזכור שלמתודה אונרית (printString) יש קדימות גבוהה יותר ממתודה בינארית (@).

פתרון מלא:

א. ללא הרווח, נקודה כמו 3 @ -4 הייתה מודפסת כ-3@-4. בשפת Smalltalk רצף של שני תווים מיוחדים ללא רווח מתפרש כמפעיל בינארי יחיד בשם @- (שאינו קיים!). הוספת הרווח כאשר y הוא מספר שלילי מפיקה '3@ -4', שהוא קוד Smalltalk תקני לחלוטין שמשערך את עצמו חזרה לנקודה 3 @ -4.

ב. (1) (3 @ 4) printString מחזיר את המחרוזת '3@4' (הנקודה 3@4 היא Self-Evaluating).
(2) 3 @ 4 printString (ללא סוגריים בקוד): ההודעה האונרית 4 printString מתבצעת ראשונה ומחזירה '4', ואז מתבצעת ההודעה הבינארית 3 @ '4' המחזירה מופע של Point שבו x = 3 ו-y = '4'! (אך אם נסמן 3 @ 4 בחלון העבודה ונלחץ Ctrl+p, המערכת מעריכה תחילה את כל הביטוי לנקודה ואז מדפיסה 3@4).
(3) {3@4 . 4.5} מדפיס {3@4 . 4.5} — מכיוון שכל איבריו הם Self-Evaluating, גם המערך הדינמי הזה הוא Self-Evaluating.
(4) {3@4 . 4+5} מדפיס {3@4 . 9} — מכיוון שהביטוי 4+5 חושב ל-9, פלט ההדפסה שונה מהביטוי המקורי ולכן אינו Self-Evaluating.

בעיה 2: התנהגות מחרוזות (ByteString), מוטביליות ב-at:put: ושרשור ב-,

ByteString vs Symbol

נתונה סדרת הביטויים הבאה על מחרוזות מסוג ByteString:

s1 := 'hello' copy.
s2 := 'hello' copy.
s1 = s2.
s1 == s2.
s1 at: 1 put: $H.
s1 := s1 , ' world'.

הסבירו מהו הערך של s1 = s2 ו-s1 == s2 בהתחלה, כיצד משפיעה ההודעה s1 at: 1 put: $H על s1 ועל s2, ומה ההבדל בין הפעולה של at:put: לפעולה של אופרטור השרשור , בשורה האחרונה.

🧭 איך לגשת לבעיה? אסטרטגיית פתרון ודגשים

זכרו ש-ByteString היא מוטבילית ונשמרת כמופעים עצמאיים בזיכרון (בניגוד ל-Symbol). יש להבדיל בין מתודה שמשנה את המופע הקיים במקום (In-place) לבין מתודה שמקצה ומחזירה מחרוזת חדשה.

פתרון מלא:

1. שוויון מול זהות: המחרוזות s1 ו-s2 מכילות אותה סדרת תווים ולכן s1 = s2 מחזיר true. מאחר שהן שני מופעים נפרדים בזיכרון, s1 == s2 מחזיר false (הערה: עבור ליטרלים באותה מתודה ללא copy, המהדר עשוי לשתף מצביע או ליצור מופעים נפרדים, אך בעת שינוי ב-at:put: כל מופע נפרד שומר על עצמאותו; ב-Symbol לעומת זאת תמיד מתקיים #hello == #hello ➔ true).

2. שינוי במקום (s1 at: 1 put: $H): משנה את התו הראשון של s1 ל-'Hello' מבלי להקצות מחרוזת חדשה, ואינו משפיע על s2 (שנשארת 'hello').

3. שרשור (s1 := s1 , ' world'): האופרטור פסיק (,) אינו משנה את המחרוזת הקיימת בגלל שגודלה של מחרוזת (ArrayedCollection) קבוע! הוא יוצר ומחזיר מחרוזת חדשה לגמרי באורך 11 ('Hello world') והמשתנה s1 מכוון להצביע עליה.

בעיה 3: איטרטור inject:into: עם מערכים מקוננים והשוואת shallowCopy מול copyTwoLevel

נתון קטע הקוד הבא:

c := a shallowCopy.
d := a copyTwoLevel.

א. מהו ערכו המדויק של a לאחר השורה הראשונה?
ב. מה יחזירו הביטויים: (1) a == b, (2) a == c, (3) a = c, (4) (a at: 1) == (c at: 1), (5) (a at: 1) == (d at: 1), (6) ((a at: 1) at: 1) == ((d at: 1) at: 1)?
ג. אם נריץ כעת (a at: 1) at: 2 put: 99, באילו מהמשתנים a, b, c, d יופיע המספר 99?

🧭 איך לגשת לבעיה? אסטרטגיית פתרון ודגשים

עקבו אחרי inject:into: איטרציה אחר איטרציה כאשר בכל צעד הצובר הקודם x והאיבר החדש y נעטפים במערך דינמי בן 2 איברים {x . y}. לאחר מכן בדקו את רמת העומק: shallowCopy מפרידה רק את רמה 1, ואילו copyTwoLevel מפרידה את רמות 1 ו-2 (אך רמה 3 נשארת משותפת!).

פתרון מלא:

א. ערכו של a הוא מערך מקונן בעומק 4: #(#(#(#(#() 1) 2) 3) 4). ברמה העליונה של a יש שני איברים: a at: 1 הוא תת-המערך #(#(#(#() 1) 2) 3), ו-a at: 2 הוא המספר 4.

ב. (1) a == b ➔ true (השמת מצביע לאותו עצם).
(2) a == c ➔ false (shallowCopy יוצרת מערך מעטפת חדש).
(3) a = c ➔ true (אותו תוכן לוגי).
(4) (a at: 1) == (c at: 1) ➔ true (ב-shallowCopy תת-המערך ברמה 2 משותף!).
(5) (a at: 1) == (d at: 1) ➔ false (ב-copyTwoLevel תת-המערך ברמה 2 שוכפל!).
(6) ((a at: 1) at: 1) == ((d at: 1) at: 1) ➔ true (רמה 3 כבר אינה משוכפלת ב-copyTwoLevel ולכן משותפת!).

ג. הפקודה (a at: 1) at: 2 put: 99 משנה את האיבר השני של תת-המערך ברמה 2 (מחליפה את 3 ב-99). לכן השינוי יופיע ב-a, b ו-c, אך לא יופיע ב-d (שבו (d at: 1) at: 2 יישאר 3)!

בעיה 4: השוואת Set, Bag ו-IdentityBag – שוויון ואי-שוויון

שאלת בחינה • 24 נק'

נתון קטע הקוד הבא:

startArray := ________________________.
b := Bag newFrom: startArray.
d := IdentityBag newFrom: startArray.
b = d ifTrue: [Transcript show: 'equal'] ifFalse: [Transcript show: 'not equal'].

א. השלימו את הגדרת המערך הלא-ריק startArray כך שיודפס 'equal'.
ב. השלימו את הגדרת המערך הלא-ריק startArray כך שיודפס 'not equal', והסבירו מדוע נוצר ההבדל.

🧭 איך לגשת לבעיה? אסטרטגיית פתרון ודגשים

Bag סופר מופעים במילון רגיל (Dictionary לפי = ו-hash), בעוד IdentityBag סופר מופעים ב-IdentityDictionary (לפי == ו-identityHash). כמו כן, המתודה Bag >> = aBag בודקת שלכל איבר ב-self מתקיים (aBag occurrencesOf: assoc key) = assoc value!

פתרון מלא:

א. כדי שיודפס 'equal': נבחר איברים שבהם שוויון ערכי (=) מתלכד עם זהות בזיכרון (==), כגון סימבולים או מספרים שלמים קטנים: startArray := #(#a #a #b) (או #(1 2 1)). בשני האוספים #a יופיע עם מונה 2 ו-#b עם מונה 1, ולכן b = d יחזיר true.

ב. כדי שיודפס 'not equal': נכניס שני עצמים ששווים בערכם (=) אך אינם אותו עצם בזיכרון (~~), למשל שתי נקודות או מחרוזת וסימבול או שתי מחרוזות משוכפלות: startArray := {3@4 . 3@4} (או {'abc' copy . 'abc' copy} או {'abc' . #abc}). במקרה של {3@4 . 3@4}, בתוך b (Bag) שתי הנקודות שוות לפי = ולכן מתמזגות למפתח אחד עם מונה 2 (b occurrencesOf: p1 ➔ 2). לעומת זאת, בתוך d (IdentityBag) שתי הנקודות הן מופעים שונים בזיכרון (p1 ~~ p2) ולכן נשמרות כשני מפתחות נפרדים עם מונה 1 לכל אחד (d occurrencesOf: p1 ➔ 1). לכן b = d יחזיר false!

🧭 איך לגשת לבעיה? אסטרטגיית פתרון ודגשים

בסעיף א' הבלוק של collect: לוכד בסגור לקסיקלי את המשתנה החיצוני sum; מכיוון שערך של ביטוי השמה sum := sum + x ב-Smalltalk הוא הערך החדש של sum, הוא ייאסף ישירות למערך התוצאה! בסעיף ב' השתמשו ב-self do: וביציאה לא-מקומית ^foundBlock value: each.

פתרון מלא: 
"א. חישוב סכומים מצטברים באמצעות collect: וסגור לקסיקלי:"
sum := 0.
b := #(1 2 3 4) collect: [:each | sum := sum + each].
"איטרציה 1: sum=1 -> 1; איטרציה 2: sum=3 -> 3; איטרציה 3: sum=6 -> 6; איטרציה 4: sum=10 -> 10. תוצאה: #(1 3 6 10)"

"ב. מימוש detect:ifFound:ifNone: במחלקה Collection:"
Collection >> detect: aBlock ifFound: foundBlock ifNone: exceptionBlock
    self do: [:each |
        (aBlock value: each)
            ifTrue: [^foundBlock value: each]].
    ^exceptionBlock value
