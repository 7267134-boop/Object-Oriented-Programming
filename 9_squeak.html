1. סעיף 9.1: מבט-על (Overview) – 8 הכלים המרכזיים של סביבת Squeak

מיפוי מלא של ארגז כלי הפיתוח המשלימים את הכלים שהכרנו בפרקים הקודמים

שלום לך! עד עכשיו כבר הכרנו את אבני היסוד של Smalltalk והתחלנו לכתוב קוד בסיסי. כעת אני רוצה לקחת אותך אל מאחורי הקלעים של סביבת העבודה Squeak ולהראות לך לעומק את ארגז הכלים המתקדם שלה. כלים אלו משלימים את הכלים שהכרנו קודם לכן, ויחד הם מעניקים לנו שליטה מלאה בניהול מארזי תוכנה, בבחינה ושינוי של עצמים חיים בזיכרון, ובגולת הכותרת של Smalltalk — ניפוי שגיאות ופיתוח קוד חי בזמן ריצה באמצעות ה-Debugger.

בוא נמפה תחילה את 8 קבוצות הכלים המרכזיות שנחקור לאורך הפרק:

🧭 1. System Browser

כלי הפיתוח הראשי והמרכזי המשמש להצגה, לכתיבה וליצירה של מחלקות ומתודות.

📦 2. Monticello

כלי ייעודי ומתקדם לניהול, שמירה, שיתוף וטעינה של חבילות ומארזי תוכנה (Packages).

🔬 3. Inspector ו-Explorer

כלים המשמשים לבחינה, להצגה, לשינוי ולאינטראקציה ישירה עם המצב הפנימי של עצמים בזיכרון.

🐞 4. Debugger

מעבר לניפוי שגיאות, מתפקד כסביבת עבודה מלאה המאפשרת הוספה, שינוי וכתיבת קוד חי בזמן אמת ישירות בתוך מחסנית הקריאות בעת עצירה.

⚙️ 5. Process Browser

כלי לבחינה ולשליטה בתהליכים השונים (Threads/Processes) הרצים בו-זמנית ברגע נתון בתוך סביבת העבודה.

🔎 6. Method Finder ו-Message Names

מתודות וכלים לאיתור וחיפוש קוד ומתודות לפי שם, לפי חלק משם או לפי דוגמת קלט ופלט.

🗂️ 7. Change Set Browser ו-Change Sorter

כלים לבחינה ולניהול של אוסף ומקבצי השינויים (Change Sets) שבוצעו בסביבת העבודה.

📁 8. File List Browser

סייר קבצים מובנה להצגת מערכת הקבצים של מערכת ההפעלה, ניווט בה, צפייה בקבצים וטעינת קוד.

2. סעיף 9.2: כלי ה-System Browser, ה-Package Browser והמחלקה SystemNavigation

שורת 8 כפתורי הפעולה, קידוד הצבעים של כפתור ה-inheritance, תפריטי ההקשר והניווט הפרוגרמטי

ה-System Browser הוא כלי הפיתוח העיקרי שלנו ליצירת מחלקות ולהצגתן. ממש במרכז החלון שלו (מתחת לארבע חלוניות הניווט של הקטגוריות, המחלקות, הפרוטוקולים והמתודות) ממוקמת שורת כפתורים ייעודיים המאפשרת לנו לקבל מידע נוסף ולבחון את הקוד מכל זווית אפשרית. בוא נעבור יחד על כל אחד מ-8 הכפתורים האלה:

1. browse קיצור: Ctrl+b

פותח חלון System Browser נוסף וממוקד סביב הפריט הנבחר, כדי שתוכל לעיין במחלקות שונות תוך כדי כתיבת הקוד.
💡 דגש שימושי חשוב: כאשר סמן העכבר ממוקם על חלונית/רשימת הקטגוריות (החלונית השמאלית ביותר), לחיצה על הקיצור Ctrl+b מבצעת פעולת back... — הצגת רשימה של המחלקות שהוצגו לאחרונה לצורך בחירה וניווט מהיר לאחור!

2. senders מי שולח את ההודעה?

פותח דפדפן (browser) ייעודי המציג את רשימת כל המתודות במערכת השולחות את ההודעה הנבחרת. לחיצה על הכפתור מציגה תחילה את רשימת ההודעות שהמתודה הנוכחית שולחת בעצמה, ולאחר בחירת הודעה מהרשימה, מוצגת בחלון ייעודי רשימת כל שולחי ההודעה ההיא.

3. implementors מי מממש את המתודה?

מציג את רשימת כל המחלקות והמתודות במערכת המממשות את ההודעה/המתודה הנבחרת. ניתן לגשת לפעולה זו גם מתוך תפריט ההקשר של חלון רשימת המתודות.

4. versions היסטוריית גרסאות

מציג ב-browser ייעודי את היסטוריית הגרסאות הקודמות והשינויים של המתודה הנוכחית (מתוך קובץ ה-changes), מאפשר לעיין בהן, מדגים את ההבדלים ביניהן, ומאפשר לחזור לגרסה קודמת.

5. inheritance (וצבעי החיווי החכמים שלו!) שרשרת הירושה והדריסה של המתודה

מציג ב-browser ייעודי את שרשרת הירושה של המתודה — רשימת המתודות במעלה היררכיית הירושה המוגדרות מחדש (overridden) על ידי המתודה הנוכחית. צבע הכפתור עצמו משתנה דינמית ומספק מידע חיוני על אופי הגדרתה של המתודה:

🌸 ורוד (Pink) הגדרה מחדש (דריסה מלאה) של מתודה ממחלקת-העל ללא שימוש במתודת מחלקת-העל (ללא super).
🟢 ירוק (Green) הגדרה מחדש של מתודה ממחלקת-העל תוך שימוש בגרסת מחלקת-העל (שימוש ב-super).
🟡 צהוב / זהב (Gold) המתודה הנוכחית מוגדרת מחדש (נדרסת) בתת-מחלקה במורד העץ.
🟠 כתום (Orange) שילוב: המתודה מגדירה מחדש מתודה ממחלקת-העל (ללא super), וגם מוגדרת מחדש בתת-מחלקה.
🟣 סגול (Purple) שילוב עמוק: מגדירה מחדש מתודה של מחלקת-העל תוך שימוש ב-super, וגם מוגדרת מחדש בתת-מחלקה.
6. hierarchy Hierarchy Browser

מציג ב-browser ייעודי (Hierarchy Browser) את עץ / היררכיית הירושה המלאה של המחלקה הנוכחית, וכך ניתן לראות בקלות פרטים על מתודות שנורשו ממחלקות-העל.

7. vars משתני מופע ומחלקה

מציג רשימה של משתני המופע או של משתני המופע והמחלקה (נקבע לפי מצב הבחירה בכפתורי ה-instance וה-class שמתחת לרשימת המחלקות). הרשימה כוללת גם משתנים שהתקבלו בירושה, ובחירה במשתנה תציג ב-browser ייעודי באילו מתודות נעשה בו שימוש.

8. source בחירת אופן תצוגת הקוד

מאפשר לבחור את אופן הצגת הקוד (התצוגה שתוצג בחלונית המרכזית של ה-System Browser) — כגון קוד מקור רגיל, bytecode, גרסאות מתועדות ותצוגות שונות של המתודה הנבחרת.

🖱️ פקודות מרכזיות בתפריטי ההקשר (כפתור ימני / צהוב)

  • file out: מייצא את הקוד לקובץ מקור חיצוני (.st) — ניתן להפעלה על קטגוריה שלמה, מחלקה בודדת או מתודה יחידה בהתאם לעצם/חלון הנבחר.
  • find class… (מחלונית הקטגוריות): חיפוש מהיר של מחלקה לפי שמה המדויק/המלא או לפי חלק משם.
  • Browse Protocol (מחלונית המחלקות): פותח דפדפן ייעודי המציג את כלל המתודות שהמחלקה מבינה, לרבות כל המתודות שהיא ירשה ממחלקות-העל במעלה ההיררכיה.
  • Browse Hierarchy / Show Hierarchy (מחלונית המחלקות): מציג את עץ הירושה של המחלקה בחלון ייעודי (Browse Hierarchy) או ישירות בחלונית המרכזית של ה-System Browser עצמו (Show Hierarchy).

🗂️ דפדפן המארזים – Package Browser (package pane browser)

בסביבת Squeak מחלקות מאורגנות בקטגוריות, ושמות של קטגוריות רבות מכילים מקף (-) המפריד בין תחום ראשי לתחום משני (לדוגמה: Kernel-Objects, Kernel-Numbers, Collections-Strings).

הכלי Package Browser (מופעל מתפריט העולם דרך World -> open… -> package pane browser) מפצל את חלונית הקטגוריות השמאלית לשתי חלוניות נפרדות להקלת החיפוש וההתמצאות:
• החלונית השמאלית: מציגה את השמות הראשיים (משמאל למקף – למשל Kernel, Collections).
• החלונית השנייה: מציגה את השמות המשניים / תתי-הקטגוריות של השם הראשי שנבחר (מימין למקף – למשל Objects, Numbers).

🤖 המחלקה SystemNavigation (שליטה תכנותית)

כלי הדפדפן (System Browser) הוא בעצמו מופע הנשען על שירותיה של המחלקה SystemNavigation (מקטגוריית System-Support), המשמשת כמנוע הניווט הפרוגרמטי של המערכת. הגישה אליה מתבצעת דרך מופע ה-Singleton שלה: SystemNavigation default.

"1. פתיחת חלון מחלקה:"
SystemNavigation default browseClass: EllipseMorph.
"2. פתיחת עץ הירושה של מחלקה:"
SystemNavigation default browseHierarchy: EllipseMorph.
"3. איתור כל שולחי ההודעה (Senders):"
SystemNavigation default browseAllCallsOn: #drawOn:.

1. סעיף 9.3: ניהול מארזים ותצורה באמצעות Monticello

מהות המארז (Package), כלל הבלעדיות, פרוטוקול כוכבית (*), המחלקה PackageInfo ומבנה Monticello Browser

כשאנחנו בונים מערכת תוכנה אמיתית, אנחנו לא עובדים על מחלקה בודדת במנותק, אלא מאגדים את העבודה שלנו לתוך חבילות תוכנה מסודרות. בסביבת Squeak, כלי ברירת המחדל לניהול תצורה ומארזים (Package Management ו-Version Control) נקרא Monticello. הכלי הזה מאפשר לנו יצירה, טעינה, עיון, שמירה, השוואת גרסאות (Diff), מיזוג (Merge) והפצה של חבילות תוכנה — הן באופן מקומי והן מרשת האינטרנט.

📦 מהו מארז (Package) ומהו כלל הבלעדיות?

מארז (Package) הוא אוסף מאוגד של מחלקות ומתודות בעלות זיקה משותפת הקשורות למערכת מסוימת (לדוגמה, מערכת SqueakLink הכוללת קטגוריות כמו Model-SqueakLink).

1. מקרה הבוחן: הוספת המתודה suffix למחלקה String וקריסת התוכנית

איך ניסיון תמים לחלץ סיומת של שם קובץ מוביל לשגיאת NotFound ופותח לנו צוהר אל ה-Debugger

הדרך הטובה ביותר להכיר את עוצמתו של ה-Debugger ב-Squeak היא להפעיל אותו מול קוד חי המכיל שגיאה. בוא נציב לעצמנו משימה מעשית: אנחנו רוצים להוסיף למחלקה String מתודה חדשה בשם suffix, שמניחה שהמחרוזת מייצגת שם קובץ ומחזירה את הסיומת שלו — כלומר את החלק שמופיע לאחר הנקודה (למשל, עבור 'readme.txt' אנו מצפים לקבל 'txt').

נתחיל במימוש הראשוני הבא (שבו מסתתרים מספר באגים מלמדים במיוחד):

suffix
    "assumes that I'm a file name, and answers my suffix, the part after the dot"
    | dot dotPosition |
    dot := FileDirectory dot.
    dotPosition := (self size to: 1 by: -1) detect: [:i | (self at: i) = dot].
    ^ self copyFrom: dotPosition to: self size

כעת אנחנו ניגשים ל-Workspace, רושמים את הביטוי 'readme.txt' suffix ומריצים אותו באמצעות print it. במקום לקבל 'txt', הביצוע נכשל ומיד קופץ חלון התראה של שגיאת ריצה: NotFound: Object is not in the collection.

  1. DoIt (הרצת הביטוי מחלונית העבודה)
  2. ByteString(String)>>suffix (המתודה שלנו)
  3. Interval(Collection)>>detect: (חיפוש הנקודה)
  4. Interval(Collection)>>detect:ifNone:

🎛️ מבנה חלון ה-Debugger ושורת 7 כפתורי הבקרה

לחיצה על כפתור Debug (או על אחת משורות ה-trace) פותחת את ה-Debugger המלא. במרכזו מוצג קוד המתודה המסומנת עם הדגשת הביטוי שנכשל, בתחתיתו מוצגים משתני המקבל (self ושדות המופע משמאל) ומשתני ההקשר הפעיל (thisContext, משתנים מקומיים וארגומנטים מימין), ובמרכזו שורת 7 כפתורי הבקרה:

  • • Proceed: המשך ביצוע התוכנית כרגיל.
  • • Restart: איפוס המסגרת הנוכחית וחזרה לשורה הראשונה (לראש) של המתודה הנבחרת לצורך הרצה מחדש.
  • • Into: כניסה לתוך המתודה הנקראת (Step Into).
  • • Over: ביצוע השורה הנוכחית ומעבר לשורה הבאה (Step Over).
  • • Through: צעידה וכניסה לתוך בלוק קוד (Step Through – למשל מעקב שלב-אחר-שלב אחרי ריצת הבלוק בתוך do: / detect:).
  • • Where: סימון והצגת מיקום הביצוע הנוכחי.
  • • Full Stack: הצגת המחסנית המלאה עד רמת המערכת הבסיסית ביותר.

2. שלושת שלבי הניפוי והתיקון החי של suffix בתוך ה-Debugger

איך אנחנו מאתרים ומתקנים את שלושת הבאגים תוך כדי ריצה מבלי לסגור את החלון

באג 1 · מחרוזת מול תו (String vs. Character) $. = '.' --> false!

כשאנחנו בוחרים את המסגרת ByteString(String)>>suffix, לוחצים על Restart וצועדים לתוך הבלוק של לולאת ה-detect: באמצעות Through ו-Over, אנו רואים בחלונית המשתנים הימנית התחתונה שהאינדקס i יורד מ-10 ל-1. אבל גם כש-i מגיע לאינדקס 7 (שבו נמצאת הנקודה במחרוזת 'readme.txt'), הבדיקה (self at: i) = dot נכשלת והלולאה לא עוצרת!
מדוע? משום שהביטוי FileDirectory dot מחזיר מחרוזת בעלת תו בודד ('.'), ואילו ההודעה self at: i מחזירה מופע של תו ($.)! ב-Smalltalk תו ומחרוזת הם עצמים מטיפוסים שונים לחלוטין ולעולם אינם שווים!
התיקון החי ב-Debugger: ישירות בחלונית הקוד של ה-Debugger אנו משנים את השורה הראשונה ל-dot := FileDirectory dot asCharacter., שומרים באמצעות accept (s) (הקוד מתהדר ומוטמע מיידית!), ולוחצים על Restart.

באג 2 · הנקודה עצמה נכללת בתוצאה ('.txt' במקום 'txt') dotPosition + 1

לאחר התיקון הראשון המתודה רצה ואינה קורסת, אך היא מחזירה את המחרוזת '.txt' (כולל הנקודה עצמה באינדקס 7) במקום להחזיר רק את הסיומת 'txt'!
התיקון: עלינו להתחיל את חיתוך המחרוזת מיקום אחד אחרי הנקודה: ^ self copyFrom: dotPosition + 1 to: self size.

באג 3 והפתרון הסופי המושלם · מחרוזת ללא נקודה כלל ('readme') detect: [...] ifNone: [self size]

מה יקרה אם נפעיל את המתודה על שם קובץ שאינו מכיל נקודה כלל (כגון 'readme')? מתודת ה-detect: תסרוק את כל המחרוזת, לא תמצא נקודה, ותקרוס שוב עם שגיאת NotFound!
הפתרון האלגנטי והסופי: נחליף את detect: במתודה detect:ifNone:, ונעביר לה בלוק חלופי המחזיר במקרה של היעדר נקודה את אורך המחרוזת כולה ([self size]):

suffix
    "assumes that I'm a file name, and answers my suffix, the part after the dot"
    | dot dotPosition |
    dot := FileDirectory dot asCharacter.
    dotPosition := (self size to: 1 by: -1) detect: [:i | (self at: i) = dot ] ifNone: [self size].
    ^ self copyFrom: dotPosition + 1 to: self size

💡 שים לב לאלגנטיות המתמטית: כשאין נקודה במחרוזת (למשל 'readme' שאורכה 6), המשתנה dotPosition מקבל 6 (`self size`), ואז הביטוי self copyFrom: 7 to: 6 (כלומר מ-self size + 1 עד self size) מחזיר באופן טבעי מחרוזת ריקה ('')!

1. סעיף 9.6: Process Browser (דפדפן התהליכים)

בחינה, ניטור ושליטה בכל התהליכים הרצים בו-זמנית בתוך סביבת העבודה

בסביבת הריצה של Squeak פועלים בו-זמנית מספר רב של תהליכים (Processes / Threads). כלי ה-Process Browser מאפשר לנו לבחון, לנטר ולשלוט בכל התהליכים השונים הרצים ברגע נתון במערכת.

🚪 איך פותחים את ה-Process Browser?

• מתפריט העולם: World -> open… -> process browser
• משורת התפריטים העליונה: Tools -> Process Browser

⚙️ יכולות ניהול ושליטה בתהליכים:

• צפייה ברשימת כל התהליכים הפעילים וברמת העדיפות (Priority) שלהם במעבד.
• בחינת מחסנית הקריאות הפעילה של כל תהליך.
• שליטה במצב התהליך: השהיה (Suspend), חידוש פעולה (Resume), שינוי עדיפות, או סיום כפוי (Terminate) של תהליכים שנתקעו או נכנסו ללולאה אינסופית.

2. סעיף 9.7: איתור מתודות – Method Finder מול Message Names

חיפוש לפי שם או לפי דוגמת קלט/פלט לעומת צפייה נוחה בקוד ללא פתיחת חלונות נוספים

בארגז הכלים העצום של Squeak קיימות אלפי מתודות מוכנות. איך נמצא את המתודה שאנחנו צריכים? לשם כך עומדים לרשותנו שני כלים משלימים:

🔎 1. Method Finder (סייר המתודות)

Example-based

פתיחה: World -> open… -> method finder | Tools -> Method Finder

  • חיפוש לפי שם או חלק משם (substring): הקלדת מחרוזת (לדוגמה time) מציגה את כל המתודות ששמן כולל מחרוזת זו.
  • חיפוש לפי דוגמה (Example-based search): הקלדת ביטוי המדגים את פעולת המתודה (קלט מול פלט רצוי) בתבנית מקבל . ארגומנטים . תוצאה צפויה מופרדים בנקודות — למשל הקלדת 4 . 16 מחזירה את הזיהוי 4 squared --> 16!
  • אופן הצגת התוצאה: בחירת מתודה מהרשימה מציגה את המחלקות הכוללות אותה, ובחירה בה פותחת חלון System Browser חדש המציג את הקוד המלא של המתודה.

💬 2. Message Names (שמות הודעות)

נוח לעבודה שוטפת!

פתיחה: World -> open… -> message names

  • ייעוד ומאפיינים: כלי ממוקד לאיתור מתודות לפי שמן המלא או לפי תת-מחרוזת המוכלת בשמן (אפשרויות החיפוש שלו מצומצמות יותר כי אינו מחפש לפי דוגמת קלט/פלט).
  • יתרונו המעשי הבולט: נוח בהרבה לעבודה יומיומית שוטפת, משום שהוא מציג את המתודות ואת קוד המקור שלהן ישירות בחלונית התחתונה הפנימית שלו, ובכך חוסך פתיחה של חלונות System Browser חדשים!
  • דוגמה: חיפוש המחרוזת suffix מציג בחלונית השמאלית את כל שמות ההודעות המכילות מילה זו (sourceFileSuffixes, suffix, suffixOf:). בחירה ב-suffix מציגה בחלונית העליונה הימנית את String suffix, ובחירה בה מציגה את קוד המקור המלא ישירות בחלונית העריכה התחתונה!

3. סעיף 9.8: ניהול מקבצי שינויים – Change Set Browser ו-Change Sorter

איך מאורגנים השינויים בזיכרון (Change Sets), המקבץ הפעיל היחיד והעברת שינויים בין מקבצים

כל שינוי קוד, הגדרת מחלקה, הוספת מתודה או מחיקה שאנחנו מבצעים במהלך העבודה אינם נשמרים רק בקובץ ה-.changes, אלא מאורגנים בזיכרון בתוך מקבצים מובנים הנקראים Change Sets (מקבצי שינויים). סביבת העבודה מכילה מספר מקבצי שינויים במקביל, אך בכל רגע נתון קיים מקבץ פעיל יחיד (Current Change Set) שאליו מתנקזים ומתועדים כל השינויים השוטפים המבוצעים באותו רגע (כברירת מחדל נושא שם כגון Unnamed1).

📋 1. Change Set Browser (Simple Change Sorter)

World -> open… -> simple change sorter | מתפריט Tools

  • חלונית שמאלית עליונה: רשימת מקבצי השינויים, תוך הדגשת המקבץ הפעיל הנוכחי.
  • חלונית ימנית עליונה: רשימת המחלקות שהשתנו במקבץ הנבחר (למשל String {Collections-Strings}).
  • חלונית אמצעית (מרכזית): רשימת המתודות שהשתנו במחלקה הנבחרת (למשל suffix {as yet unclassified}).
  • חלונית תחתונה: מציגה את קוד המקור של המתודה שנבחרה מתוך המקבץ.
  • תפריטי הקשר: מאפשרים להסיר שינויים מתוך המקבץ, למחוק מחלקות או מתודות מרשימת השינויים של המקבץ, ולשנות את שמו.

🔀 2. Change Sorter – Dual Change Sorter

World -> open… -> dual change sorter | מתפריט Tools

מורכב בפועל משני חלונות Change Set Browsers המוצבים זה לצד זה באותו החלון!
תפקידו המרכזי: מאפשר להעביר (להעתיק/לגרור) ולמזג שינויים — הן מחלקות שלמות והן מתודות בודדות — ממקבץ שינויים אחד למקבץ שינויים אחר באופן חזותי ונוח.

4. סעיפים 9.9–9.10: סייר הקבצים (File List Browser) ושחזור קוד שאבד (Code Recovery)

ניווט במערכת הקבצים עם סרגל כפתורים דינמי, ושחזור מלא של קוד מתוך קובץ ה-.changes ומקבצי השינויים

📁 סעיף 9.9: File List Browser (סייר הקבצים)

סרגל דינמי

World -> open… -> file list | Tools -> file list

מאפשר לנווט, לצפות ולנהל את מערכת הקבצים של המחשב (מערכת ההפעלה המארחת) ישירות מתוך Squeak:
• חלונית שמאלית: עץ תיקיות היררכי לניווט בכונני המחשב ובתיקיית ה-Resources של Squeak.
• חלונית ימנית עליונה: רשימת הקבצים בתיקייה שנבחרה (שם הקובץ, תאריך ושעת עדכון אחרון, וגודל בבתים).
• חלונית תחתונה/מרכזית: תוכנו של הקובץ שנבחר.

⚡ סרגל פעולות דינמי לקובצי קוד (.st או .mcz): שורת הכפתורים מתעדכנת דינמית בהתאם לסוג הקובץ שנבחר! כשנבחר קובץ קוד מופיעים כפתורים ייעודיים:
• file in: טעינה והידור של כל הקוד שבקובץ ישירות לתוך סביבת העבודה.
• browse: פתיחת דפדפן קוד לקריאת המחלקות והמתודות שבקובץ מבלי לטעון אותן למערכת.
• changes: בחינת השינויים וההבדלים בין הקוד בקובץ לבין הקוד הקיים ב-image.
• install: התקנה מלאה של המארז למערכת.

🛟 סעיף 9.10: שחזור קוד שאבד (Code Recovery)

Changes Log

מנגנון ההגנה של מקבצי השינויים (Change Sets) וה-Changes Log: כל פעולת עריכה, הגדרת מחלקה, שמירת מתודה וביצוע פקודת do it נשמרים במקבצי השינויים ונרשמים באופן טקסטואלי ורציף אל תוך קובץ ה-.changes במחשב!

לכן, גם אם סביבת העבודה נסגרה בפתאומיות, קרסה, המשתמש יצא ללא שמירה (quit ללא save), או שקוד נמחק בטעות — המידע אינו אובד!

🛠️ שלושת שלבי השחזור המעשי: 1. ניגשים לתפריט העולם דרך World -> changes... -> recover lost changes... או בוחרים באפשרות recent changes.
2. נפתח דפדפן שינויים ייעודי המציג ציר זמן כרונולוגי של כל הפעולות שנרשמו בקובץ השינויים עד לרגע הסגירה או התקלה.
3. מסמנים את שורות השינויים הרצויות ובוחרים בפקודה להרצתן מחדש (replay / file in), וכך הקוד משוחזר במלואו לתוך תמונת המערכת הנוכחית!

🐞 מעבדת ה-Debugger החיה על המתודה String>>suffix (9.5)

ה-Debugger ב-Squeak מאפשר לערוך קוד חי בתוך מחסנית הקריאות, לשמור ב-accept (s) ולהריץ מחדש מהתחלת המתודה באמצעות Restart: 

suffix
    "assumes that I'm a file name, and answers my suffix, the part after the dot"
    | dot dotPosition |
    dot := FileDirectory dot asCharacter.
    dotPosition := (self size to: 1 by: -1) detect: [:i | (self at: i) = dot ] ifNone: [self size].
    ^ self copyFrom: dotPosition + 1 to: self size
