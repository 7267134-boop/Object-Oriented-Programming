1. מבוא לפרק וסעיף 5.1: להכיר את המשחק Quinto ואת ארכיטקטורת התוכנה שלנו

איך אנחנו בונים אפליקציה גרפית שלמה מתחילתה ועד סופה בתוך סביבת העבודה Squeak

עכשיו הגענו לאחד הרגעים הכי מרגשים בלמידה שלנו: אנחנו הולכים לפתח יחד, צעד אחר צעד, אפליקציה ראשונה שלמה בעלת ממשק גרפי מתחילתה ועד סופה — המשחק Quinto (המבוסס על המשחק הלוגי המוכר Lights Out). המטרה שלי איתך בפרק הזה היא שתרגיש בידיים איך הקוד והמחלקות נבנים בצורה הדרגתית בתוך סביבת העבודה Squeak, תוך שימוש אינטואיטיבי באלמנטים המרכזיים של שפת Smalltalk: הגדרת מחלקות וירושה, מתודות אתחול, משתני מופע מול משתנים מקומיים, טיפול באירועים גרפיים, שרשור הודעות, בלוקים, איתור באגים וייצוא קוד — וכל זאת עוד בטרם נערוך את הדיון הפורמלי בכללי התחביר שיוצג בפרק 6!

בוא נבין תחילה איך מתנהל המשחק Quinto ומהם חוקיו המדויקים:

🟨 חוקי המשחק והממשק של Quinto

  • הלוח והמצבים: המשחק משוחק על גבי לוח משובץ (מטריצה ריבועית של משבצות) המורכב ממשבצות בצבע אפור (מצב כבוי – המצב ההתחלתי) או צהוב (מצב דלוק/פעיל).
  • מכניקת הלחיצה (Toggle לשכנים): לחיצה על משבצת כלשהי בלוח גורמת לשינוי צבען ומצבן (Toggle) של ארבע המשבצות השכנות הצמודות לה בלבד: המשבצת שמעליה (למעלה), מתחתיה (למטה), מימינה ומשמאלה — ללא האלכסונים!
  • הפיכת מצב והפיכות הפעולה: משבצת שכנה שהייתה אפורה תהפוך לצהובה, ומשבצת שהייתה צהובה תהפוך לאפורה. לחיצה נוספת על אותה המשבצת תחזיר את המשבצות השכנות לצבען הקודם.
  • מטרת המשחק: לגרום לכך שכל משבצות הלוח תהפוכנה לצהובות!

🏗️ ארכיטקטורת התוכנה ויצירת הקטגוריה SBE-Quinto

כדי למדל את המשחק בחשיבה מונחית עצמים נקייה, נפריד את התוכנית שלנו לשתי מחלקות עיקריות:

  1. SBEGame: תייצג את לוח המשחק השלם, תנהל את לוגיקת המשחק ותחזיק את מטריצת המשבצות.
  2. SBECell: תייצג משבצת (תא) בודדת על גבי הלוח.
📂 יצירת הקטגוריה ב-System Browser: את שתי המחלקות נגדיר תחת קטגוריה חדשה בשם SBE-Quinto (ראשי תיבות: Squeak By Example - Quinto). הוספת הקטגוריה מתבצעת מתוך תפריט ההקשר (לחיצה ימנית / כפתור צהוב) בחלונית הקטגוריות השמאלית ביותר של ה-System Browser ← בחירה באפשרות add item… ← הזנת השם SBE-Quinto ולחיצה על אישור.

2. סעיף 5.2: הגדרת המחלקה SBECell ב-System Browser

איך תבנית יצירת המחלקה ב-Smalltalk שולחת הודעת מילת-מפתח למחלקת-העל SimpleSwitchMorph

ברגע שאנחנו בוחרים בקטגוריה החדשה שלנו SBE-Quinto ב-System Browser, חלונית העריכה המרכזית מציגה לנו תבנית בסיסית ליצירת מחלקה חדשה:

Object subclass: #NameOfSubclass
    instanceVariableNames: ''
    classVariableNames: ''
    poolDictionaries: ''
    category: 'SBE-Quinto'

עצור לרגע ותתבונן בביטוי הזה! בשפות כמו Java אנחנו כותבים מילים שמורות מיוחדות של המהדר (public class SBECell extends ...). אבל ב-Smalltalk הכל הוא אובייקט וכל דבר קורה על ידי שליחת הודעה! הביטוי הזה מורכב משליחת הודעת מילת-מפתח ארוכה בת 5 חלקים: subclass:instanceVariableNames:classVariableNames:poolDictionaries:category: הנשלחת ישירות אל העצם שמייצג את מחלקת-העל (בתבנית זוהי המחלקה Object). הארגומנטים של ההודעה כוללים:

  • סימבול שם המחלקה (#NameOfSubclass): נרשם עם הסימן סולמית # בראשו ומציין את שם המחלקה החדשה.
  • instanceVariableNames: מחרוזת המכילה את רשימת משתני המופע (מופרדים ברווח).
  • classVariableNames: מחרוזת המכילה את רשימת משתני המחלקה.
  • poolDictionaries: מחרוזת המכילה את רשימת המילונים המשותפים.
  • category: שם הקטגוריה שבה תסווג המחלקה ('SBE-Quinto').

כעת נשנה את זהות מקבל ההודעה (מחלקת-העל) וכן חלק מהארגומנטים, כך שההודעה תתאים ליצירת המחלקה SBECell שלנו:

SimpleSwitchMorph subclass: #SBECell
    instanceVariableNames: 'mouseAction'
    classVariableNames: ''
    poolDictionaries: ''
    category: 'SBE-Quinto'
🔘 למה אנחנו יורשים מ-SimpleSwitchMorph?

במקום לרשת מ-Object ולבנות גרפיקה מאפס, ההודעה נשלחת למחלקה SimpleSwitchMorph — מחלקה קיימת שמוגדרת בקטגוריה MorphicExtras-Widgets ומייצגת כפתור/מתג גרפי דו-מצבי (כבוי ודלוק)! בנוסף, אנו מגדירים משתנה מופע אחד בשם mouseAction שישמור את פעולת התגובה ללחיצת עכבר.

💾 שמירה ב-accept (s) ותיעוד (Class Comment)

שומרים את השינויים על ידי בחירת האפשרות accept (s) מתוך תפריט ההקשר (או Ctrl+s). כתוצאה מהשמירה נוצרת המחלקה SBECell ושמה מוצג בחלונית המחלקות! בחלונית התחתונה אפשר להוסיף תיעוד קצר (Class Comment) המתאר את מטרת המחלקה ולשמור שוב.

1. סעיף 5.3: הוספת מתודת האתחול initialize למחלקה SBECell

איך פועלת מוסכמת האתחול האוטומטי ב-Smalltalk, וניתוח שורה-אחר-שורה של קוד האתחול

עכשיו כשיש לנו את המחלקה SBECell, אנחנו רוצים שכל תא חדש שייווצר יקבל מיד את המראה המדויק של משבצת במשחק Quinto. לפי המוסכמות של שפת Smalltalk, מיד לאחר יצירת עצם חדש (באמצעות שליחת ההודעה new למחלקה), נשלחת אל העצם החדש באופן אוטומטי ההודעה initialize המיועדת לאתחול העצם.

מה תפקידן של מתודות אתחול? לאתחל את משתני המופע של העצם! אבל שים לב לנקודה קריטית: משתני המופע של עצם כוללים גם את כל המשתנים שהעצם ירש ממחלקת-האב (במקרה שלנו מ-SimpleSwitchMorph וממחלקות-העל שלה), ולא רק את המשתנה mouseAction שהגדרנו בהודעה שיצרה את המחלקה SBECell. לכן המתודה initialize חייבת לדאוג לאתחל גם אותם!

כשנבחר בפרוטוקול --all-- בחלונית הפרוטוקולים של ה-System Browser, תוצג לנו בחלון העריכה המרכזי התבנית הכללית ליצירת מתודה:

messageSelectorAndArgumentNames
    "comment stating purpose of message"
    | temporary variable names |
    statements

נחליף את התבנית הזו במתודה initialize של המחלקה SBECell ונשמור באמצעות accept (s):

initialize
    super initialize.
    self label: ''.
    self borderWidth: 2.
    bounds := 0@0 corner: 16@16.
    offColor := Color paleYellow.
    onColor := Color paleBlue darker darker.
    self useSquareCorners.
    self turnOff

🔬 בוא ננתח יחד כל שורה במתודת ה-initialize:

  • 1. super initialize.: המשפט הראשון שולח ל-super את ההודעה initialize. המילה super מתייחסת לחלק העצם שהתקבל בירושה ממחלקת-העל (SimpleSwitchMorph). הודעה זו מפעילה את המתודה initialize שהוגדרה במחלקת-העל כדי שזו תאתחל את כל משתני המופע שהוגדרו אצלה!
  • 2. self label: ''. ו-self borderWidth: 2.: המתודה שולחת לעצמה (self) את ההודעות label: (איפוס התווית למחרוזת ריקה כך שלא יופיע טקסט על התא) ו-borderWidth: (קביעת עובי מסגרת של 2 פיקסלים). הודעות אלה מפעילות את המתודות המתאימות שהתקבלו בירושה ממחלקת-העל.
  • 3. bounds := 0@0 corner: 16@16.: השמה ישירה למשתנה המופע bounds שהתקבל בירושה ממחלקת-העל. המשתנה מאותחל כמלבן (Rectangle) שפינתו השמאלית-עליונה בנקודה (0,0) ופינתו הימנית-תחתונה בנקודה (16,16). איך נוצר המלבן? על ידי שליחת ההודעה @ עם ארגומנט מספרי למספר שלם שיוצרת עצם מסוג נקודה (Point), ושליחת ההודעה corner: לעצם ה-Point עם נקודת הפינה הנגדית!
  • 4. offColor := Color paleYellow. ו-onColor := Color paleBlue darker darker.: משפטי השמה למשתני המופע offColor ו-onColor שהתקבלו בירושה ממחלקת-העל. offColor מאותחל כצהוב חיוור, ו-onColor מאותחל בגרסה כהה פעמיים של כחול חיוור (על ידי שרשור שתי הודעות אונריות darker לעצם הצבע שחזר מ-Color paleBlue).
  • 5. self useSquareCorners. ו-self turnOff: לבסוף, המתודה שולחת לעצמה הודעות להשתמש בפינות מרובעות וישרות (במקום מעוגלות) ולכבות את עצמה כמצב התחלתי. גם הודעות אלה מפעילות מתודות שנורשו ממחלקת-העל.

2. סעיף 5.4: יצירת עצם ובחינתו באמצעות ה-Inspector וה-Morphic Halo

איך אנחנו בודקים את התא שיצרנו בעולם החי של Squeak עוד לפני שבנינו את לוח המשחק

אחד הדברים הכי יפים בעבודה בסביבת Squeak הוא שאנחנו לא צריכים לחכות לסיום כתיבת התוכנית כולה כדי לבדוק אם התא שלנו עובד! בוא נעבור לחלון העבודה (Workspace), ניצור עצם חדש מסוג SBECell באמצעות שליחת ההודעה new למחלקה, ונפעיל עליו את המפקח (Inspector) באמצעות הפקודה inspect it (i) (או Ctrl+i):

SBECell new    "סמן ובצע inspect it (i)"
🔍 1. חלוניות ה-Inspector ושינוי bounds

בחלונית השמאלית של ה-Inspector מוצגים כל משתני המופע של העצם (כולל אלו שנורשו!), ובחלונית הימנית אפשר לראות ולשנות את ערכו של המשתנה הנבחר. למשל, נבחר במשתנה bounds ונשנה את ערכו כך שפינתו הימנית-תחתונה של המלבן תהיה בנקודה (100,100).

🌍 2. הצגה בעולם החי עם self openInWorld

1. הגדרת המחלקה SBEGame ומתודת ה-initialize של הלוח

ירושה מ-BorderedMorph, משתנים מקומיים זמניים, חישוב גודל הלוח ב-extent: ויצירת מטריצת התאים

המחלקה SBEGame מייצגת את לוח המשחק הכולל, והיא תכיל מטריצה ריבועית של עצמים מסוג SBECell. מכיוון שאנחנו רוצים שללוח המשחק שלנו תהיה מסגרת גרפית יפה עם שוליים, נגדיר את SBEGame כתת-מחלקה של BorderedMorph (צורה גרפית בעלת מסגרת ושוליים) תחת הקטגוריה SBE-Quinto:

BorderedMorph subclass: #SBEGame
    instanceVariableNames: ''
    classVariableNames: ''
    poolDictionaries: ''
    category: 'SBE-Quinto'

שים לב שבשלב הראשוני השארנו את רשימת משתני המופע ריקה (''), ומיד נראה כיצד סביבת Squeak תעזור לנו להוסיף לשם את משתנה המופע cells באופן אוטומטי כשנשמור את מתודת האתחול! בוא נכתוב כעת את המתודה initialize של SBEGame (בפרוטוקול --all--):

initialize
    | sampleCell width height n |
    super initialize.
    n := self cellsPerSide.
    sampleCell := SBECell new.
    width := sampleCell width.
    height := sampleCell height.
    self bounds: (5@5 extent: ((width*n) @ (height*n)) + (2 * self borderWidth)).
    cells := Matrix new: n tabulate: [ :i :j | self newCellAt: i at: j].

🔍 ניתוח מעמיק של מתודת SBEGame>>initialize:

  • משתנים מקומיים | sampleCell width height n |: בשורה הראשונה מוגדרים 4 משתנים מקומיים זמניים (בין קווים אנכיים | ... |). הם משמשים אותנו לחישוב בזמן ריצת המתודה בלבד, ואינם נשמרים כחלק ממצב העצם לאחריה!
  • super initialize.: מפעילה את מתודת ה-initialize של מחלקת-העל (BorderedMorph).
  • מדידת תא דוגמה: n מאותחל למספר התאים בצלע הלוח באמצעות self cellsPerSide. לאחר מכן אנו יוצרים תא זמני sampleCell := SBECell new רק כדי לשאול אותו מהם הרוחב (width) והגובה (height) של תא בודד!
  • קביעת גבולות הלוח עם bounds: ו-extent:: אנו שולחים לעצמנו את ההודעה bounds: (שנורשה) ומעבירים לה מלבן שנוצר על ידי שליחת ההודעה extent: לנקודת הפינה השמאלית-עליונה 5@5. ההודעה extent: מקבלת נקודה המייצגת את גודל המלבן (רוחב וגובה כוללים): מכפלת רוחב וגובה תא בודד ב-n, בתוספת כפליים עובי המסגרת של הלוח (2 * self borderWidth – עבור השוליים משני הצדדים!).
  • יצירת המטריצה עם Matrix new: n tabulate:: השורה האחרונה מאתחלת את משתנה המופע cells כמטריצה בגודל $n \times n$. ההודעה new:tabulate: נשלחת למחלקה Matrix ומקבלת את הגודל n ובלוק קוד [ :i :j | self newCellAt: i at: j] שמתבצע עבור כל שורה i ועמודה j ומייצר את התא המתאים!
  • שמירה, הגדרת cells כמשתנה מופע וסיווג אוטומטי: כשנשמור (accept) את המתודה, המערכת תתריע כי המשתנה cells והמתודות החדשות טרם הוגדרו. נבחר עבור cells באפשרות יצירת משתנה מופע (declare instance variable)! תחילה המתודה תופיע תחת הפרוטוקול "as yet unclassified". נבחר בפעולה "categorize all uncategorized" מתפריט ההקשר של חלונית הפרוטוקולים — והמערכת תיצור אוטומטית את הפרוטוקול initialization ותשייך אליו את initialize (מכיוון שגם במחלקת-העל המתודה initialize משויכת לפרוטוקול initialization!).

2. פרוטוקול חדש game logic ב-SBEGame

המתודה toggleNeighboursOfCellAt: i at: j

בודקת תנאי שפה (כדי לא לחרוג מגבולות המטריצה), שולפת כל שכן מ-cells עם at:at: ושולחת לו toggleState. (נסווג בפרוטוקול חדש game logic באמצעות new category...).

toggleNeighboursOfCellAt: i at: j
    "toggle Neighbours Of Cell ij"
    (i > 1) ifTrue: [(cells at: i-1 at: j) toggleState].
    (i < self cellsPerSide) ifTrue: [(cells at: i+1 at: j) toggleState].
    (j > 1) ifTrue: [(cells at: i at: j-1) toggleState].
    (j < self cellsPerSide) ifTrue: [(cells at: i at: j+1) toggleState].
3. פרוטוקול initialization ב-SBEGame (הגרסה הראשונית בסעיף 5.5) שים לב לשורה האחרונה שמעבירה בלוק קוד לתא!

המתודה newCellAt: i at: j – יצירת התא, מיקומו בלוח והגדרת פעולת הלחיצה

מתודה זו מקבלת מספר שורה i ועמודה j, יוצרת תא חדש c := SBECell new, מאתרת את נקודת המוצא הפנימית של הלוח (origin := self innerBounds origin), מוסיפה את התא כרכיב גרפי מוכל בלוח (self addMorph: c), ממקמת אותו לפי קואורדינטות השורה והעמודה שלו, ובשורה האחרונה שולחת לתא את ההודעה mouseAction: עם בלוק קוד שירוץ בעת לחיצת עכבר:

newCellAt: i at: j
    "create a cell for position (i,j) and add it to the game at appropriate position.
    return the new cell"
    | c origin |
    c := SBECell new.
    origin := self innerBounds origin.
    self addMorph: c.
    c position: ((i-1) * c width) @ ((j-1) * c height) + origin.
    c mouseAction: [self toggleNeighboursOfCellAt: i at: j].

כל משתני המופע בשפת Smalltalk הם פרטיים (Private), והדרך היחידה לגשת אליהם מחוץ לעצם עצמו היא דרך מתודות גישה! בניגוד לשפות אחרות, מתודות גישה ב-Smalltalk אינן משתמשות בקידומת get או set: שמה של מתודת הגישה להחזרת ערכו של משתנה זהה לשם המשתנה (mouseAction), ושמה של מתודת העדכון זהה לשם המשתנה בתוספת נקודתיים (mouseAction:). נוסיף למחלקה SBECell שתי מתודות:

  1. הקשר הביצוע (Stack Trace): חלון ה-Debugger מציג לנו את מחסנית הקריאות בעת שהבעיה התעוררה. אנו רואים שהבעיה התעוררה מתוך המתודה toggleNeighboursOfCellAt:at: המוגדרת במחלקה SBEGame, בעת ניסיון לשלוח את ההודעה toggleState לתאים השכנים.
  2. השאלה המתבקשת: המתודה toggleState מוגדרת עבור תא (SBECell, שירש אותה מ-SimpleSwitchMorph). מדוע ההודעה toggleState נשלחה לעצם מסוג SBEGame ולא לעצם מסוג SBECell?!
  3. מציאת העדות המפלילה: בפקודה (cells at: i-1 at: j) toggleState, מי שמקבל את ההודעה toggleState הוא האיבר שחזר מההודעה at:at: שנשלחה למשתנה המופע cells! אם חזר משם עצם מסוג SBEGame, פירוש הדבר שהמטריצה cells מכילה את לוח המשחק עצמו במקום את התאים!
  4. שורש הבאג ב-newCellAt:at:: איך אותחלה המטריצה cells במתודה initialize של SBEGame? על ידי השורה:
    cells := Matrix new: n tabulate: [ :i :j | self newCellAt: i at: j].
    כלומר, בכל תא במטריצה cells הושם הערך המוחזר מההודעה newCellAt:at:! כשנסתכל שוב במתודה newCellAt:at: שכתבנו בסעיף 5.5, נגלה שהיא יוצרת תא c, מוסיפה אותו ללוח הגרפי ומגדירה לו מיקום ופעולה — אולם שכחנו להחזיר בה את התא c שנוצר!
