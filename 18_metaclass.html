חלק VII: מטה-מחלקות • יחידה 18.1 סגירת מעגל ההפשטה של מודל העצמים

ייצוג מחלקה באמצעות עצם: אם מחלקה היא עצם — מי המחלקה שלה?

הכרת מושג ה"מטה-מחלקה" (Metaclass) כיחידת ההפשטה המייצגת מחלקה של מחלקה, תכונת האנונימיות (Implicit), וחקירת שרשרת ההודעות true class... עד להתכנסות למעגל סגור (Fixed Point).

🧬
🧠

מודל מנטלי ועיקרון מנחה: כש"הכל הוא עצם" פוגש את "כל עצם הוא מופע של מחלקה"

💡 האנלוגיה המוחשית

תבנית אפייה מייצרת עוגיות, אבל מי ייצר את תבנית האפייה עצמה? מפעל ליצירת תבניות! ב-Smalltalk, עוגייה היא עצם רגיל, תבנית האפייה היא המחלקה (Class), והמפעל שמייצר את התבנית הזו הוא המטה-מחלקה (Metaclass)!

⚖️ חוק הברזל הפדגוגי

ב-Smalltalk כל דבר במערכת הוא עצם (כולל המחלקות Object, Color, Point), וכל עצם הוא בהכרח מופע של מחלקה. לכן כל מחלקה היא מופע של מטה-מחלקה אנונימית שהגישה אליה נעשית על ידי שליחת ההודעה class אל עצם המחלקה.

🎯 תובנת המפתח

שרשור חוזר של ההודעה class (כמו true class class class...) אינו ממשיך לאינסוף! החל מהצעד השלישי והרביעי אנו מתכנסים למעגל סגור (Fixed Point) המתחלף לסירוגין בין Metaclass לבין Metaclass class.

1. שאלת היסוד שסוגרת את מעגל העקביות ב-Smalltalk

איך שני כללי היסוד שלנו מובילים בהכרח להולדת המושג "מטה-מחלקה" (Metaclass)

אנחנו מגיעים עכשיו אל שיא הארכיטקטורה של Smalltalk — המקום שבו כל חלקי הפאזל שבנינו מתחברים למערכת אחת שלמה, עקבית וסגורה. בוא נזכיר לעצמנו את עקרון היסוד שליווה אותנו מהרגע הראשון ב-Smalltalk: כל דבר במערכת הוא עצם (Everything is an object), וכל עצם הוא בהכרח מופע של מחלקה (Every object is an instance of a class).

עכשיו בוא נחשוב יחד כמו מהנדסי שפות תכנות: אם כל דבר במערכת הוא עצם, נובע מכך ישירות שגם המחלקות עצמן (כגון Object, Color, Point או True) הן עצמים חיים בזיכרון! אנחנו הרי שולחים להן הודעות כל הזמן (כמו Point new או Color blue). אבל אם מחלקה היא עצם, מיד מתעוררת השאלה הלוגית המתבקשת: של איזו מחלקה היא מופע?

💎

הגדרת המושג: מטה-מחלקה (Metaclass)

מחלקה שהמופעים שלה הם בעצמם מחלקות נקראת מטה-מחלקה (Metaclass). זוהי יחידת ההפשטה המטפלת במנגנון של "מחלקה של מחלקה".

🕵️ מטה-מחלקות הן אנונימיות (Implicit): למטה-מחלקה אין שם עצמאי גלובלי משלה במערכת! אז איך אנחנו ניגשים אליה? אנחנו פונים אל עצם המחלקה ושולחים לו את ההודעה אונארית class. למשל: שליחת class למחלקה Color מחזירה את המטה-מחלקה שלה, שנקראת פשוט Color class, ושליחת class ל-Object מחזירה את Object class.

2. ניסוי מחשבתי חי: שרשור ההודעה true class...

מה קורה כשאנחנו שואלים שוב ושוב "ומהי המחלקה של המחלקה הזו?" לאורך 7 שלבים עוקבים?

כדי לראות במו עינינו איך סביבת Squeak עונה על השאלה "מי המחלקה של המטה-מחלקה?", בוא ניקח את העצם הבוליאני הפשוט true ונשלח אליו את ההודעה class שוב ושוב בשרשרת של 7 שלבים:

1
true class

המופע הבוליאני true הוא מופע יחיד של המחלקה True (תת-מחלקה של Boolean). לכן מוחזרת המחלקה True.

2
true class class

כעת אנו שואלים את המחלקה True מהי המחלקה שלה. מוחזרת המטה-מחלקה האנונימית שלה: True class.

3
true class class class

מהי המחלקה של מטה-מחלקה (True class)? כל המטה-מחלקות במערכת הן מופעים של מחלקה אחת מיוחדת: מוחזרת המחלקה Metaclass!

4
true class class class class

ומהי המחלקה של Metaclass? מכיוון שגם Metaclass היא מחלקה, יש לה מטה-מחלקה משלה: מוחזרת Metaclass class!

5–7
true class class class class class ➔ Metaclass ➔ Metaclass class ➔ Metaclass

בשלב 5 אנחנו שואלים: מהי המחלקה של Metaclass class? מכיוון ש-Metaclass class היא בעצמה מטה-מחלקה, היא מופע של Metaclass!
בשלבים 6 ו-7 (וכך עד אינסוף) אנו נכנסים למעגל סגור (Fixed Point) המתחלף לסירוגין בין Metaclass class לבין Metaclass — וכך נמנעת רגרסיה אינסופית!

1. סעיף 18.2: סיווג עצמים לשלוש שכבות היררכיות (Meta-levels)

הבחנה בין מופעים סופיים (Terminal Instances), מחלקות (Classes) ומטה-מחלקות (Metaclasses)

כדי שנבין לעומק מדוע סביבת Squeak בנויה דווקא במודל של 5 רמות, בוא נסווג תחילה את העצמים בעולם התוכנה שלנו לשלוש שכבות היררכיות עקרוניות לפי יכולת היצירה (Instantiation) שלהם:

שכבה 1 · Terminal Instances

1. עצמים פשוטים / מופעים סופיים

עצמים בקצה השרשרת שאינם מסוגלים לייצר עצמים חדשים. למשל: מופעים של תווים, מחרוזות, נקודות, או בדוגמת היצירות הספרותיות והבימתיות: המופעים "אותלו", "מקבת", "כטוב בעיניכם" (מופעי מחזמר/מחזה) ו-"1984", "אוליבר טוויסט", "מלחמה ושלום" (מופעי רומן).

שכבה 2 · Classes

2. מחלקות (עצמים מייצרי מופעים)

עצמים המסוגלים לייצר מופעים סופיים. בדוגמה שלנו אלו הן המחלקות "מחזמר" ו-"רומן" (Novel), או בשפה שלנו המחלקות Point, Color ו-String.

שכבה 3 · Metaclasses

3. מטה-מחלקות (מייצרות מחלקות)

עצמים המסוגלים לייצר מחלקות חדשות (כגון המחלקה הגנרית Class או מטה-המחלקות ב-Squeak). המופעים שלהן הם המחלקות מהשכבה השנייה!

2. סעיפים 18.3–18.7: התפתחות מערכות העצמים – מרמה 1 ועד 5 רמות

איך שפות התכנות מונחות העצמים נבדלות זו מזו במספר ה"רמות" במודל העצמים שלהן, ומה פתר כל שלב?

18.3 · רמה 1: מערכת של עצמים בלבד (Prototype-based) דוגמאות: שפת Self, JavaScript (במודל המקורי)

אפיון: מערכת "שטוחה" ללא מחלקות כלל. כל עצם מתאר את עצמו באופן עצמאי (טבלה של שמות וערכים — שדות ומתודות ייעודיים), ויצירת עצמים חדשים נעשית באמצעות שכפול (Cloning) של עצם אב-טיפוס קיים (Prototype), תוך שיתוף התנהגות באמצעות מצביעי parent ו-traits.

18.4 · רמה 2: מערכת עצמים בת 2 רמות דוגמאות: שפת Eiffel (אייפל), ++C המסורתית

אפיון: קיימת הבחנה ברורה בין עצמים למחלקות (עצמים מתוארים על ידי מחלקות), אך המחלקות עצמן אינן עצמים בזמן ריצה! הן מתקיימות כיישויות תחביריות בזמן הידור בלבד, אינן מיוצגות כעצמים חיים בזיכרון ואינן מסוגלות לקבל הודעות.

18.5 · רמה 3: מערכת עצמים בת 3 רמות (מטה-מחלקה יחידה) דוגמאות: Smalltalk-76, Little Smalltalk

אפיון: המחלקות הן עצמים חיים בזמן ריצה המגיבים להודעות, וכל המחלקות כולן הן מופעים של מטה-מחלקה גנרית יחידה ומשותפת (הנקראת לרוב Class), היורשת מהמחלקה הגנרית "עצם" (Object) ומגדירה את המבנה האופייני של מחלקה (משתני מופע, מצביע למחלקת-על, מילון מתודות) ואת מתודת היצירה המשותפת new.
⚠️ המגבלה המרכזית: מכיוון שכל המחלקות הן מופעים של אותה מטה-מחלקה יחידה (Class), לכל המחלקות יש בדיוק את אותן מתודות מחלקה ואת אותם משתני מחלקה! לא ניתן להגדיר בנאים ייחודיים לכל מחלקה (כמו Point x: 3 y: 4 או Color r:g:b:) מבלי לחשוף אותם לכל שאר המחלקות במערכת!

18.6 · רמה 4: מערכת עצמים בת 4 רמות דוגמאות: שפות LOOPS, ObjVlisp

אפיון: פותרת את מגבלת רמה 3 בכך שהיא מאפשרת להגדיר מטה-מחלקה פרטית לכל מחלקה (או לשתף מטה-מחלקה בין מספר מחלקות), וכך לכל מחלקה יכולים להיות מתודות מחלקה ומשתני מחלקה ייחודיים משלה (ומדיניות יצירת מופעים עצמאית). כל המטה-מחלקות הפרטיות הללו הן מופעים של מטה-מחלקה גנרית משותפת אחת ("מטה-עצם" / "המטה-מחלקה בה' הידיעה"), היורשת מ"עצם".

18.7 · רמה 5: מודל ה-Explicit Metaclass (5 רמות) דוגמאות: Squeak ו-Smalltalk-80

אפיון: לכל מחלקה נוצרת אוטומטית מטה-מחלקה פרטית משלה שמתארת רק אותה, וגרף הירושה של המטה-מחלקות חופף ומקביל לגרף הירושה של המחלקות הרגילות. כל המטה-מחלקות הן מופעים של המחלקה הגנרית Metaclass, שלה עצמה יש מטה-מחלקה משלה (Metaclass class). המודל פותר את בעיית הרגרסיה האינסופית ("מי יצר את המטה-מחלקה?") באמצעות קשר מעגלי סגור בין Metaclass ל-Metaclass class!

2. הוכחת החוקים בקוד חי: Color, TranslucentColor ו-EllipseMorph

פירוק שורת הקוד של אליפסה בכחול שקוף וזיהוי כל העצמים וההודעות שבה

בוא ננתח בדיוק אילו הודעות נשלחות כאן ולאילו עצמים:

  • ההודעה blue נשלחת אל עצם המחלקה Color ומחזירה מופע של Color.
  • ההודעות alpha: 0.4 ו-class נשלחות אל עצם הצבע: שליחת alpha: 0.4 לצבע הכחול יוצרת ומחזירה עצם חדש (שנקרא לו translucentBlue), שהוא מופע של תת-המחלקה TranslucentColor!
  • מחלקת-העל (superclass) של TranslucentColor היא Color, ומחלקת-העל של Color היא Object (ההודעה superclass נשלחת לעצם המחלקה).
  • ההודעות color: ו-openInWorld נשלחות בשרשור (Cascade עם ;) אל המופע החדש שנוצר מהמחלקה EllipseMorph.

3. סעיף 18.9: כיצד מאותרת המתודה class בעת שליחתה ל-translucentBlue?

מעקב דו-שלבי: קפיצת "מופע של" (קו מקווקו) ואחריה טיפוס בשרשרת "יורשת מ-" (קו רציף)

  1. מעבר מהעצם למחלקתו (Instance of): המקבל הוא העצם translucentBlue. מנגנון האיתור פונה אל המחלקה שממנה הוא נוצר — TranslucentColor.
  2. חיפוש ב-TranslucentColor: האם המתודה class מוגדרת ב-TranslucentColor? לא!

1. סעיף 18.10: חוק 6 – כל מחלקה היא מופע של מטה-מחלקה (Rule 6)

6 עובדות הברזל של מטה-מחלקות וההודעות שאנחנו יכולים לשלוח למחלקות כעצמים חיים

כעת אנו נכנסים אל חמשת החוקים המשלימים של המודל (חוקים 6–10), העוסקים במטה-מחלקות. חוק 6 קובע: Every class is an instance of a metaclass (כל מחלקה היא מופע של מטה-מחלקה). בכל פעם שאנחנו יוצרים מחלקה חדשה במערכת (למשל Color), נוצרת עבורה אוטומטית מטה-מחלקה פרטית יחידה (Color class), והמחלקה Color היא המופע היחיד שלה.

📌 6 עובדות הברזל שעליך לזכור על מטה-מחלקות:

1. המופעים שלהן הם מחלקות: מטה-מחלקות הן מחלקות לכל דבר, שמופעיהן הם עצמי המחלקות במערכת.
2. נוצרות אוטומטית: אינך יוצר מטה-מחלקה ידנית; היא נוצרת אוטומטית ברגע שאתה מגדיר מחלקה חדשה.
3. מופע יחיד בלבד (Singleton): לכל מטה-מחלקה קיים מופע אחד ויחיד בדיוק — המחלקה שעבורה היא נוצרה!
4. אנונימיות (Implicit): מטה-מחלקות הן חסרות שם עצמאי גלובלי, בעוד שהמופעים שלהן (המחלקות) משמשים כמשתנים גלובליים.
5. גישה באמצעות ההודעה class: ההתייחסות למטה-מחלקה נעשית תמיד דרך המופע היחיד שלה — שליחת Color class מחזירה את המטה-מחלקה של Color.
6. קשר מופע ולא ירושה! הקשר בין TranslucentColor לבין TranslucentColor class הוא "מופע של"; היא אינה תת-מחלקה שלה! מחלקת-העל שלה היא Color.

💬 אילו הודעות ניתן לשלוח למחלקה בהיותה עצם?

  • subclasses – מחזירה מערך של תתי-המחלקות הישירות שלה.
  • allSuperclasses – מחזירה אוסף של כל מחלקות-העל שלה בשרשרת הירושה.
  • instVarNames – מחזירה מערך עם שמות משתני המופע שהוגדרו במחלקה עצמה.
  • allInstVarNames – מחזירה את כל שמות משתני המופע, כולל אלו שהוגדרו במחלקות-העל!

🔎 מה מציג חלון ה-Inspector כשבוחנים עצם ומחלקה?

כאשר אתה פותח את כלי ה-Inspector על עצם (כגון הצבע הכחול Color blue), כותרת חלון ה-Inspector מציגה את שם המחלקה שלו (Color) ולא את שם העצם עצמו, כדי לאשר מאיזה טיפוס הוא נוצר. וכאשר תפתח Inspector על עצם המחלקה Color עצמה, הכותרת תציג את מחלקתה — כלומר Color class!

2. סעיף 18.11: חוק 7 – היררכיית המטה-מחלקות מקבילה להיררכיית המחלקות!

אפקט הראי, ירושת מתודות מחלקה (blue), ומסלול איתור המתודה TranslucentColor new

חוק 7 קובע: The metaclass hierarchy parallels the class hierarchy. היררכיית הירושה של המטה-מחלקות מקבילה ומשתקפת באופן מושלם להיררכיית הירושה של המחלקות הרגילות! כלומר, המטה-מחלקה של מחלקת-העל היא מחלקת-העל של המטה-מחלקה:

TranslucentColor       --inherits--> Color       --inherits--> Object
TranslucentColor class --inherits--> Color class --inherits--> Object class
TranslucentColor class superclass superclass  --> Object class

מהי המשמעות האדירה של חוק 7? המשמעות היא שמתודות מחלקה מורשות בדיוק כמו מתודות מופע! בוא נבחן שני תרחישים מרתקים שמוכיחים זאת:

🔵 תרחיש 1: שליחת TranslucentColor blue ושכתוב (Overriding)

כאשר אנו שולחים את ההודעה blue אל המחלקה TranslucentColor:
1. החיפוש מתחיל במחלקתה של המקבלת — ב-TranslucentColor class.
2. המתודה אינה שם, ולכן החיפוש עולה אל מחלקת-העל שלה — Color class, שם blue מוגדרת ומחזירה כחול רגיל!
💡 שאלה לדיון: כיצד נגרום ל-TranslucentColor blue להחזיר כחול שקוף? פשוט נגדיר (נדרוס / Override) מתודה בשם blue בתוך המטה-מחלקה TranslucentColor class!

🏆 תרחיש 2 (מלכודת הבחינה!): היכן מוגדרת ומאותרת המתודה new?

כאשר מבצעים TranslucentColor new:
1. המקבל הוא עצם המחלקה TranslucentColor.
2. החיפוש מתחיל במחלקתו — ב-TranslucentColor class (ולא ב-Color!).
3. בהיעדר דריסה מקומית, החיפוש עולה בשרשרת המטה-מחלקות: TranslucentColor class ← Color class ← Object class.
4. מ-Object class החיפוש ממשיך אל מחלקת-העל שלה Class ← ClassDescription ← ונעצר ב-Behavior, שבה המתודה new ממומשת בפועל!
5. המתודה new ב-Behavior משתמשת בערך ה-self (שהוא המקבל המקורי TranslucentColor!) ולכן מחזירה מופע חדש של TranslucentColor (ולא של Behavior)!

1. סעיף 18.12: חוק 8 – כל מטה-מחלקה יורשת מ-Class ומ-Behavior

פירוק שלוש שכבות הליבה שמעניקות למחלקות ולמטה-מחלקות את כוחן: Behavior, ClassDescription ו-Class

ראינו קודם שכל מטה-מחלקה (כמו TranslucentColor class או Color class) יורשת במעלה עץ המטה-מחלקות עד שהיא מגיעה אל Object class. אבל ממי יורשת Object class? כאן נכנס לפעולה חוק 8 (Rule 8: Every metaclass inherits from Class and Behavior): בקצה עץ המטה-מחלקות, Object class יורשת מ-Class, אשר יורשת מ-ClassDescription, אשר יורשת מ-Behavior, אשר יורשת מ-Object!

1. Behavior

שורש ההתנהגות ויצירת המופעים

מספקת את המינימום ההכרחי הנדרש למחלקה: הגדרת מבנה המופעים, הידור מתודות והרצתן, קישור להיררכיית הירושה, ומכילה את המתודות הבסיסיות ליצירת עצמים: new, basicNew, new: ו-basicNew:.

2. ClassDescription

ארגון, פרוטוקולים ומעקב שינויים

מחלקה מופשטת המרחיבה את Behavior ביכולות ארגוניות המשמשות את סביבת הפיתוח והדפדפנים: שמות מפורשים למשתני מופע, ארגון מתודות בפרוטוקולים (קטגוריות), הערות תיעוד, מעקב שינויים (Change sets) ושמירה לקובץ (file-in / file-out).
ממנה יורשות שתי מחלקות אחיות: Class ו-Metaclass!

3. Class

מחלקות בעלות שם ומשתני מחלקה

מוסיפה את המאפיינים הייחודיים למחלקות רגילות בעלות שם גלובלי (שאינם קיימים במטה-מחלקות אנונימיות!): שם המחלקה, ניהול משתני מחלקה (classVariables) ומאגרים משותפים (poolDictionaries).

2. סעיפים 18.13–18.14: חוקים 9 ו-10 – הפרדוקס הלוגי וסגירת המעגל של Metaclass

כיצד הקשר המעגלי בין Metaclass ל-Metaclass class בולם את הרגרסיה האינסופית?

עכשיו אנחנו מגיעים אל השיא האינטלקטואלי של הפרק כולו: כל מטה-מחלקה במערכת (כמו TranslucentColor class, Color class, Object class) היא עצם חי בזיכרון. ואם היא עצם, לפי חוק 2 היא חייבת להיות מופע של מחלקה כלשהי! לאיזו מחלקה שייכות כל המטה-מחלקות?

👑 חוק 9 (סעיף 18.13): Every metaclass is an instance of Metaclass

כל המטה-מחלקות במערכת הן מופעים של מחלקה אחת מיוחדת הנקראת Metaclass! וממי יורשת המחלקה Metaclass עצמה? מכיוון שמטה-מחלקות הן אנונימיות (חסרות שם גלובלי), Metaclass אינה צריכה את תכונת השם של Class, ולכן היא יורשת ישירות מ-ClassDescription (כאחות של Class)!

♾️ חוק 10 (סעיף 18.14): The metaclass of Metaclass is an instance of Metaclass

מכיוון ש-Metaclass היא מחלקה, לפי חוק 6 חייבת להיות לה מטה-מחלקה משלה: Metaclass class (היורשת מ-ClassDescription class). אבל של מי מופע היא Metaclass class? בהיותה מטה-מחלקה, לפי חוק 9 היא בעצמה מופע של המחלקה Metaclass!
כאן נסגר המעגל הסופי: Metaclass היא מופע של Metaclass class, ו-Metaclass class היא מופע של Metaclass!

2. מטה-מחלקה אנונימית ויחידה: לכל מחלקה יש מטה-מחלקה אנונימית הנוצרת אוטומטית בעת יצירתה. המחלקה היא המופע היחיד של המטה-מחלקה שלה.
3. הקבלה מלאה של ההיררכיות: היררכיית ירושת המטה-מחלקות תמיד מקבילה להיררכיית ירושת המחלקות הרגילות.
4. איתור מתודות של מחלקות: זהה לאיתור רגיל, אך מתחיל במטה-מחלקה של המחלקה המקבלת וממשיך מעלה בהיררכיית המטה-מחלקות.
5. ירושה מ-Class ומ-Behavior: מטה-מחלקות הן מחלקות, ולכן כולן יורשות בסופו של דבר מ-Class, מ-ClassDescription ומ-Behavior.
6. מטה-מחלקות כמופעים של Metaclass: מטה-מחלקות הן גם עצמים, ולכן כולן הן מופעים של המחלקה Metaclass.
7. המטה-מחלקה של Metaclass: Metaclass היא מחלקה, ולכן קיימת עבורה מטה-מחלקה (Metaclass class), ו-Metaclass היא המופע היחיד שלה.
8. ירושת Metaclass מ-ClassDescription: Metaclass היא סוג של מחלקה (עבור מחלקות אנונימיות), ולכן יורשת ישירות מ-ClassDescription.
9. הקשר המעגלי הסוגר: Metaclass class היא מטה-מחלקה ולכן היא גם עצם, ובתור שכזו היא מופע של Metaclass — זהו הקשר המעגלי במערכת!

שאלה 3 (רמת יישום): עקוב אחר ארבעת השלבים הראשונים של שרשרת ההודעות החל מהמופע הבוליאני true: מה מחזירים true class, true class class, true class class class ו-true class class class class? ▼

💡 ההסבר האינטואיטיבי שלי:
1. true class: העצם הבוליאני true הוא מופע של המחלקה True.
2. true class class: שואל מהי המחלקה של True, ומחזיר את המטה-מחלקה האנונימית שלה: True class.

4. true class class class class: שואל מהי המחלקה של Metaclass, ומחזיר את המטה-מחלקה שלה: Metaclass class.

שאלה 5 (רמת סינתזה): אם נחליף את true בביטוי (3@4) (מופע של Point), מאיזה שלב בשרשרת ההודעות class התוצאות של שניהם יתלכדו לחלוטין? ▼

שאלה 1 (רמת בסיס): מהם חמשת החוקים הבסיסיים (Rules 1–5) של מודל העצמים ב-Squeak? ▼

💡 ההסבר האינטואיטיבי שלי:
1. Rule 1 (Everything is an object): כל דבר במערכת הוא עצם.
2. Rule 2 (Every object is an instance of a class): כל עצם הוא מופע של מחלקה.
3. Rule 3 (Every class has a superclass): לכל מחלקה יש מחלקת-על (למעט שורש העץ ProtoObject).
4. Rule 4 (Everything happens by message sending): כל חישוב מתבצע אך ורק באמצעות שליחת הודעות.
5. Rule 5 (Method lookup follows the inheritance chain): איתור מתודה מתחיל במחלקת המופע ועולה במעלה שרשרת הירושה.

🎯 שורה תחתונה: חמשת החוקים האלה קובעים איך כל עצם חי, מאיפה הוא מקבל את תכונותיו, ואיך מתבצע כל חישוב במערכת.

שאלה 2 (רמת הבנה): הוכח שעבור כל מחלקה C שיש לה מחלקת-על (כלומר אינה ProtoObject), מתקיים תמיד השוויון C superclass class == C class superclass. מאיזה חוק זה נובע? ▼

💡 ההסבר האינטואיטיבי שלי: השוויון הזה הוא הניסוח האלגברי המדויק של חוק 7 (The metaclass hierarchy parallels the class hierarchy):
• אגף שמאל (C superclass class) אומר: "קח את מחלקת-העל של C, ועבור אל המטה-מחלקה שלה".
• אגף ימין (C class superclass) אומר: "קח את המטה-מחלקה של C, ועבור אל מחלקת-העל שלה". מכיוון שהיררכיית המטה-מחלקות מקבילה לחלוטין להיררכיית המחלקות, המטה-מחלקה של מחלקת-העל היא תמיד מחלקת-העל של המטה-מחלקה!

🎯 שורה תחתונה: חוק 7 שקול בדיוק לזהות הקומוטטיבית C superclass class == C class superclass (ובמקרה הקצה שבו C = Object ומנתחים ללא ProtoObject, שניהם מתקשרים לחיבור של Object class superclass --> Class).
שאלה 3 (רמת ניתוח): מה מחזיר הביטוי Metaclass superclass class == Metaclass class superclass? נתח כל אגף במדויק! ▼

💡 ההסבר האינטואיטיבי שלי:
• אגף שמאל: Metaclass superclass היא ClassDescription. שליחת class אליה מחזירה את ClassDescription class.
• אגף ימין: Metaclass class היא המטה-מחלקה של Metaclass. לפי ההיררכיה המקבילה (חוק 7), ה-superclass של Metaclass class היא ClassDescription class! לכן שני האגפים מחזירים בדיוק את ClassDescription class, והביטוי כולו מחזיר true!

🎯 שורה תחתונה: גם עבור Metaclass עצמה מתקיים חוק ההיררכיה המקבילה ללא שום יוצא מן הכלל!
שאלה 4 (רמת יישום): אם ננסה לשלוח את ההודעה new למופע סופי, למשל (Color blue) new, מה יקרה ומדוע? ▼

💡 ההסבר האינטואיטיבי שלי: המקבל הוא המופע הסופי Color blue (שאינו מחלקה!). חיפוש המתודה new יתחיל במחלקתו Color → יעלה אל Object → יעלה אל ProtoObject — ולא ימצא את המתודה new באף אחת מהן! (משום ש-new מוגדרת ב-Behavior, ו-Color יורשת מ-Object ולא מ-Behavior!). לכן המערכת תזרוק חריגת MessageNotUnderstood: Color>>new. זהו בדיוק ההבדל בין מופע סופי (Terminal Instance) לבין מחלקה!

🎯 שורה תחתונה: מופע סופי אינו יורש מ-Behavior ואינו מופע של מטה-מחלקה, ולכן אינו מבין את ההודעה new.
שאלה 5 (רמת סינתזה מסכמת): סכם בתשעה משפטים תמציתיים את כל תמונת המודל של פרק 18 (סעיף 18.15). ▼
