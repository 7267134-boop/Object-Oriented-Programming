1.1–1.11 מטרות הקורס, למה Smalltalk וסביבת העבודה Squeak

  • מדוע כדאי ללמוד Smalltalk? בדומה ל-LISP ול-LOGO, שפת Smalltalk היא שפה מונחית עצמים "טהורה" (Pure OOP) המתבססת על מנגנון הפשטה אחד ויחיד, פשוט וקליט: כל דבר הוא עצם, והתכנות מתבצע אך ורק על ידי הגדרת עצמים ושליחת הודעות ביניהם. היא כמעט נטולת תחביר ומכריחה את הסטודנט לחשוב ולתכנת בגישת OOP טהורה.
  • סביבת העבודה Squeak: סביבת פיתוח בקוד פתוח תואמת Smalltalk-80, הממומשת כולה ב-Smalltalk עצמה ובעלת מנשק גרפי עשיר (ששימש אף את אולפני Disney ביצירת סרטים).

2.1 דוגמה לשימוש במנגנוני הפשטה: מניעת חזרה על קבועים

מנגנוני הפשטה מוכרים בשפות תכנות: משתנים, קבועים, טיפוסי נתונים, פרוצדורות/פונקציות, מודולים, טיפוסי נתונים מופשטים (ADT), מחלקות וירושה.
לדוגמה, נניח שב-C++ מוגדר מערך int a[100]; ולולאה for (i = 0; i < 100; i++) cout << a[i];. להלן השוואת 4 מנגנוני הפשטה למניעת חזרה על הקבוע 100 ביתרונותיהם וחסרונותיהם:

שיטת הפשטה קוד מרכזי הערכת מנגנוני ההפשטה (יתרונות וחסרונות)
ללא הפשטה (קבוע כפול) int a[100]; ... i < 100 הבעיה בגישה זו: הקבוע 100 מופיע פעמיים; אם גודל המערך יעודכן ל-200 ויישכח עדכון תנאי הלולאה, תיווצר חוסר עקביות ושגיאות ריצה.
פקודת מאקרו ב-C++ #define N 100 מגדיר את גודל המערך במקום אחד, אך מבוצע ע"י הקדם-מעבד (Preprocessor) כהחלפת טקסט עיוורת לפני ההידור, ללא בדיקת טיפוסים או תחום הכרה (Scope).
שימוש ב-enum ב-C++ enum {N = 100}; int a[N]; יתרון לעומת מאקרו: enum הוא חלק משפת התכנות עצמה (כפוף לבדיקות המהדר, ל-Scope ולסימבולים ב-Debugger).
חיסרון לעומת קבוע ישיר: דורש שורת קוד נוספת ומפצל את הגדרת המערך וגודלו לשתי שורות נפרדות במקום שורה אחת.
מאקרו חישוב גודל #define SIZEOF(arr) (sizeof(arr)/sizeof(arr[0])) משלב את שני היתרונות: הגדרת המערך וגודלו בשורה אחת (int a[100];) והגודל אינו מופיע פעמיים, אך עדיין תלוי במאקרו קדם-מעבד.
תמיכה מובנית ב-Java a.length או for (int k : a) ב-Java תמיכה מובנית בתוך השפה: המערך הוא עצם היודע את אורכו (a.length), ובלולאת for-each תחביר הלולאה מופשט עוד יותר ללא מונה אינדקס כלל (for (int x : a))!

2.2 ★ 7 שלבי התפתחות מנגנוני ההפשטה (סעיפים 2.2.1–2.2.7)

1. אסמבלר (Assembler): ייצוג כתובות ואופרטורים בסיסיים באופן סימבולי במקום מספרי, תוך היעזרות במהדר/אסמבלר לתרגום לשפת מכונה, אך הקוד אינו מובנה.
2. ייצוג נתונים / הפשטה מבוססת נתונים (Fortran, Cobol): דגש בייצוג מבנה הנתונים הגלובלי (`Global Data`) והגדרת פעולות (`Proc 1..4`) הפועלות עליו באופן המזכיר מסדי נתונים.
3. פרוצדורות מקוננות / הפשטה מבוססת תהליכים (Pascal, C): דגש בתהליך ובאלגוריתם (תכנות מלמעלה למטה Top-Down) כאשר כל תהליך מגדיר לוקלית תת-תהליכים ומבני נתונים. החיסרון (למשל במחסנית ב-C): הסתרת המידע לוקה בכך שכדי לשתף את המחסנית בין `init()`, `push(val)`, `top()` ו-`pop()`, נדרשים משתנים גלובליים (`int datastack[100]; int datatop = 0;`).
4. מודול (Modula-2): אוסף של פרוצדורות ונתונים עם יכולת לשלוט במה שיוחצן (Export) ומה שיוסתר. המגבלה הקריטית של מודול: מודול הוא כמו עצם בודד או מחלקה עם עצם (מופע) יחיד בלבד!
5. טיפוס נתונים מופשט (ADT ב-Ada): מאפשר להגדיר טיפוס חדש שייתכנו ממנו כמה מופעים שלכל אחד סט אופרטורים משלו. בהגדרת `adt List` עם `list = Nil | CELL of integer * list`, כל פעולה כגון `empty(l)` או `tail(l)` מבצעת פיצול מקרים (`case l of Nil => ... | CELL(x, l') => ...`).
6. מחלקה (Class ב-OOP): המחלקה היא טיפוס נתונים מופשט שבו הדגש מושם בייצוג הנתונים (העצמים) במקום בייצוג הפעולות!
• לדוגמה, מוגדרות המחלקות `EmptyList` (שבה `empty = true; head = error; tail = error`) ו-`NonEmptyList(x, l)` (שבה `empty = false; head = x; tail = l`).
• השוואת מטריצת ADT מול OOP: בייצוג כ-ADT החלוקה היא לפי הפעולות (`empty?`, `head`, `tail` חוצות את העמודות `nil` ו-`cons`), ואילו בייצוג מונחה עצמים (OOP) החלוקה היא לפי טיפוסי העצמים (`nil` / `EmptyList` ו-`cons` / `NonEmptyList`), כשכל מחלקה מאגדת את מימוש כל הפעולות עבורה.
7. ירושה (Inheritance): מנגנון הפשטה המאפשר שיתוף קוד בין מחלקות. בניסוי המחשה מפורסם, ספרייה בשפת Ada באורך 125K שורות קוד מומשה מחדש בשפת C++ (בעזרת ירושה) באמצעות 10K שורות קוד בלבד!

חלק II: עצמים – המושג "עצם" (פרק 3)

סוגי עצמים, 3 מאפייני העצם (זהות, מצב, התנהגות), עצמים בשפת C, זהות עצמית, בדיקת שוויון וסוגי העתקה.

3.1–3.3 סוגי עצמים, 3 מאפייני העצם ודוגמאות

  • שאלת מפתח: איזה מושג חשוב יותר ב-OOP – "עצם" או "מחלקה"? פתרון: המושג "עצם" הוא בסיסי יותר כמובן, אך למעשה מושג ה"מחלקה" הוא חשוב יותר (כי הוא מנגנון ההפשטה המגדיר קבוצות של עצמים).
  • סיווג העצמים לשני מרחבים:
    1. עצמים השייכים למרחב הבעיה (`problem space`): מייצגים ישויות מעולם הבעיה, כגון עובד, שעון נוכחות, פריט במלאי, פטיש בחנות, מספר מרוכב $e+2i$, כלי רכב נושא לוחית זיהוי 19-070-35, או רשימה ממרחב הבעיה (כגון רשימת קניות או רשימת נוכחות תלמידים).
    2. עצמים השייכים למרחב התכנית / הפתרון (`program / solution space`): מייצגים מבני עזר תכנותיים, כגון קובץ, או רשימה ממרחב הפתרון (כגון רשימת בלוקים פנויים במנהל זיכרון או שרשרת גיבוב). שימו לב כי רשימה כגון (13, "hello", true) יכולה להשתייך הן למרחב הבעיה והן למרחב הפתרון בהתאם להקשר השימוש בה.

🔨 שלושת מאפייני העצם (זהות, מצב והתנהגות):

1. זהות (Identity) תכונה המבדילה את העצם מכל שאר העצמים (לרוב כתובת הזיכרון שבה שמור העצם). מאפשרת לקבוע אם שני שמות מתייחסים לאותו עצם ממש. זהות העצם אינה משתנה לעולם!
2. מצב (State – המאפיין הסטטי) אוסף הערכים בתכונות העצם (למשל בפטיש: מוצג למכירה; במספר מרוכב: חלק ממשי וחלק מדומה; ברכב: מהירות, מיקום, צבע). המצב יכול להשתנות לאורך חיי העצם.
3. התנהגות (Behavior – המאפיין הדינמי) אוסף הפעולות שהעצם מבצע בתגובה להודעות שהוא מקבל (למשל בפטיש: נעיצת מסמרים; ברשימה: הוספת/מחיקת איבר, מיון; ברכב: נסיעה, האצה, עצירה).

3.4 האם בשפת C אפשר להגדיר עצמים? (סעיפים 3.4.1–3.4.3)

1. פונקציה (דוגמת מונה `counter`) int counter(void) { static int n = 0; return ++n; }
• זהות: מופע הפונקציה.
• מצב: ערך המשתנה הסטטי n.
• החיסרון: ההתנהגות מנוונת (הודעה אחת בלבד – הפעלת הפונקציה) ומופע יחיד.
2. מחסנית כמודול קובץ מנשק stack.h (push, pop) וקובץ מימוש stack.c עם static int stack[100], sp;.
• מצב והתנהגות: המשתנים הסטטיים ואוסף הפונקציות בקובץ.
• החיסרון: הזהות מנוונת – יש רק מופע אחד של המחסנית!
3. מצביע לקובץ (`FILE *fin`) הדומה ביותר לעצם אמיתי!
• זהות: המצביע לקובץ (ייתכנו מצביעים רבים לקבצים שונים!).
• מצב: תוכן הקובץ.
• התנהגות: הפעולות על המצביע (fopen, feof, fgetc, סגירת הקובץ).

3.5 ★ זהות עצמית, בדיקת שוויון וסוגי העתקה

  • שם מול זהות והמזהה השמור לעצם הנוכחי: שם העצם נבדל מזהותו (ייתכנו שני עצמים בעלי אותו שם, עצם בעל כמה שמות, או עצם ללא שם כלל, אך לא ייתכנו שני עצמים בעלי אותה זהות). המזהה השמור לעצם הנוכחי: ב-C++ וב-Java: this | ב-Eiffel: Current | ב-Smalltalk: self.
  • שני סוגי השוואה: (1) השוואת הזהות: שני שמות שווים אמ"ם הזהות זהה (מצביעים לאותו עצם ממש). (2) השוואה מבנית: שני שמות שווים אמ"ם לשני העצמים יש מבנה זהה ומצב זהה.

📋 סיווג סוגי העתקת עצמים ב-Java (העתקה זהותית, רדודה, רב-שכבתית ועמוקה – חובה למבחן!):

בהעתקת רשימה מקושרת של נקודות class PList { public Point head; public PList tail; }:

  • 1. העתקה זהותית: המצביע לעצם משוכפל; בסיום ההעתקה יש שני שמות לאותו עצם ממש ונותרת זהות אחת בלבד.
  • 2. העתקה מבנית: מצב העצם מועתק לעצם חדש (בסיום יש שני עצמים בעלי זהויות שונות). נחלקת ל:
    • העתקה רדודה (`oneLevelCopy`): השורש מועתק בהעתקה מבנית (PList res = new PList();), אך העצמים הפנימיים מועתקים זהותית (res.head = head; res.tail = tail;).
    • העתקה רדודה לעומק 2 (`twoLevelCopy`): יוצרת נקודה חדשה בראש (res.head = new Point(head.x, head.y);) ומעתיקה את הזנב לעומק אחד (res.tail = tail.oneLevelCopy();).
    • העתקה עמוקה (`deepCopy`): הן השורש והן כל חוליות הזנב והנקודות הפנימיות מועתקים רקורסיבית/איטרטיבית בהעתקה מבנית עמוקה (לכל חוליה נוצרים new Point(...) ו-new PList() חדשים).
    • העתקה רקורסיבית (`copy`): ב-PList.copy() כתוב: res.head = head.copy(); if (tail != null) res.tail = tail.copy();.
      ניתוח עומק ההעתקה (האם זו העתקה רדודה או עמוקה?): עומק ההעתקה נקבע כאן ע"י העצמים הפנימיים והאופן שבו הם מממשים את copy()! אם המחלקה Point מוגדרת עם שדות קבועים public final int x, y; (כלומר Point היא עצם בלתי משתנה / Immutable שמצבו אינו יכול להשתנות לעולם), Point.copy() יכולה לממש בחוכמה return this; (העתקה זהותית של הנקודה מבלי לשכפלה לשווא בזיכרון), בעוד חוליות ה-PList משוכפלות מבנית לכל אורך הרשימה!

    | sampleCell width height n |

    sampleCell := SBECell new.

6.3–7.6 ★ 3 סוגי ההודעות, כללי קדימות, מבנה מתודה ושרשור Cascade

סדר הקדימויות בשפת Smalltalk (סעיפים 6.3 ו-7.1–7.4):

  1. 1. סוגריים עגולים ( ... ): משנים את סדר ההערכה (אך בניגוד לסוגריים מרובעים [...] אינם משפיעים על מספר הפעמים שהביטוי מוערך!).
  2. 2. הודעות אונריות (Unary – הקדימות הגבוהה ביותר!): מילה אחת (ללא נקודתיים וללא ארגומנטים), כגון 3 factorial.
  3. 3. הודעות בינריות (Binary – הקדימות השנייה!): תו אחד או יותר מתוך הסימנים המיוחדים (+ - * / \ ~ < > = @ % | & ? ,) עם ארגומנט יחיד.
    ⚠️ כלל זהב: לכל האופרטורים הבינריים יש קדימות זהה והם מוערכים משמאל לימין! (ניתן להעמיס אופרטורים אך לא לשנות את קדימותם או מספר האופרנדים שלהם).
    • דוגמאות חישוב: 3 + 4 * 5 $\implies$ 35 | 2 + 5 * 4 + 3 $\implies$ 31 | 2 raisedTo: 1 + 3 factorial $\implies$ קודם אונרי 3 factorial (=6), אז בינרי 1 + 6 (=7), ולבסוף מילת-מפתח 2 raisedTo: 7 = 128! | 2 * 3 factorial raisedTo: 2 $\implies$ (2 * 6) raisedTo: 2 = 144!
  4. 4. הודעות מילות-מפתח (Keyword – הקדימות הנמוכה ביותר!): מזהה (Selector) המורכב מרצף המילים הארוך ביותר המלוות בנקודתיים : וארגומנט.
    • חשיבות הסוגריים בהודעות מילת-מפתח: בביטוי st := 'hello'. st at: (st indexOf: $e) put: $x (שמחליף את 'e' ב-'x' ומחזיר $x כשהמחרוזת הופכת ל-'hxllo'), ללא הסוגריים המערכת הייתה מנסה לשלוח ל-st הודעה אחת שגויה בשם at:indexOf:put:!
📝 מבנה מתודה ודוגמת `LinkedList>>add:after:`: מתודה כוללת: (1) תבנית המתודה (`method pattern`), (2) הערה `"..."`, (3) הצהרת משתנים זמניים `| savedLink |`, ו-(4) משפטים מופרדים בנקודה `.`: 
LinkedList >> add: link after: otherLink
    | savedLink |
    lastLink == otherLink ifTrue: [^ self addLast: link].
    savedLink := otherLink nextLink.
    otherLink nextLink: link.
    link nextLink: savedLink.
    ^ link
🌊 דוגמאות מרכזיות לשימוש ב-Cascade (`;`): שולח סדרת הודעות לאותו מקבל שרשום לפני ה-; הראשונה, ומחזיר את ערך ההודעה האחרונה:
• 3 + 4; + 5 $\implies$ שתיהן נשלחות ל-3 $\implies$ מחזיר 8.
• 2 raisedTo: 2; * 3 factorial $\implies$ המקבל הוא 2; ההודעה השנייה * 6 נשלחת ל-2 (ולא ל-4!) $\implies$ מחזיר 12!
• 10@10 - 10; corner: 30@30; isZero $\implies$ המקבל הוא 10@10; בסוף (10@10) isZero מחזיר false! אבל בלי ה-; הראשונה: 10@10 - 10 corner: 30@30; isZero $\implies$ המקבל של ה-Cascade הוא התוצאה של 10@10 - 10 שהיא הנקודה 0@0, ולכן (0@0) isZero מחזיר true!
• (10@10 + 20; corner: 30@30) area $\implies$ מלבן מ-10@10 עד 30@30 ששטחו 400.
ניתוח ללא שימוש ב-Cascade (בלי ה-;): (10@10 + 20 corner: 30@30) area יוצר מלבן מ-30@30 עד 30@30 ששטחו 0!

  • מימוש מבני בקרה, תנאים ולולאות ב-Smalltalk:

12.5–12.6 ★ מימוש כל האיטרטורים במחלקה Collection ו-4 כללי הזהב

// מימוש איטרטורים מרכזיים באוספים (do:, collect:, select:, reject:, detect:, inject:into:):
SequenceableCollection >> do: aBlock
    1 to: self size do: [:index | aBlock value: (self at: index)]
// גרסאות נוספות של do: -> doWithout:, withIndexDo:, reverseDo:, ובמילון: keysDo:, valuesDo:, associationsDo: (במילון do: סורקת את הערכים values!)

Collection >> collect: aBlock
    | newCollection |
    newCollection := self species new.
    self do: [:each | newCollection add: (aBlock value: each)].
    ^ newCollection
// זהירות: collect: על String תחזיר String ולכן הבלוק חייב להחזיר תווים (Character), אחרת תיזרק שגיאה!

Collection >> select: aBlock
    | newCollection |
    newCollection := self species new.
    self do: [:each | (aBlock value: each) ifTrue: [newCollection add: each]].
    ^ newCollection

Collection >> reject: aBlock
    ^ self select: [:element | (aBlock value: element) == false]

Collection >> detect: aBlock
    ^ self detect: aBlock ifNone: [self errorNotFound: aBlock]

Collection >> detect: aBlock ifNone: exceptionBlock
    self do: [:each | (aBlock value: each) ifTrue: [^ each]].
    ^ exceptionBlock value

Collection >> inject: thisValue into: binaryBlock
    | nextValue |
    nextValue := thisValue.
    self do: [:each | nextValue := binaryBlock value: nextValue value: each].
    ^ nextValue
// הודעות איטרציה נוספות: count: [:each | ...] ו-anySatisfy: [:each | ...]

13–14.4 ★ רקע, ייצוג פרמוטציה ו-4 אופני הייצוג של חידת N המלכות

  • הגדרת בעיית 8 המלכות ועקרונות הסימולציה:
    • הגדרת חידת 8 המלכות: הצב 8 מלכות על לוח שחמט כך שאף מלכה אינה מאיימת על אף מלכה אחרת (אין שתי מלכות באותה שורה, באותה עמודה או באותו אלכסון).
    • רקע היסטורי: הוצגה ב-1848 ע"י שחקן השחמט מקס בזל (Max Bezzel), ונחקרה ע"י גאוס (C.F. Gauss, 1865), פוליה (G. Polya, 1918) ולוקאס (E. Lucas, 1960). במדעי המחשב היא דוגמה קלאסית לאלגוריתמי Backtracking ולסימולציה בעזרת עצמים (הגישה שהולידה את שפת Simula).
    • ייצוג פתרון כפרמוטציה: מכיוון שבכל עמודה ובכל שורה יש בדיוק מלכה אחת, ניתן לייצג פתרון כפרמוטציה מעל $\{0, 1, 2, 3, 4, 5, 6, 7\}$, למשל הפתרון החוקי: $$\begin{pmatrix} 0 & 1 & 2 & 3 & 4 & 5 & 6 & 7 \\ 7 & 3 & 0 & 2 & 5 & 1 & 6 & 4 \end{pmatrix}$$
1. ייצוג אלגברי יהא $A = \{0, 1, 2, \dots, N-1\}$ ויהא $B = A \times A = \{(0,0), (0,1), \dots, (N-1, N-1)\}$. תת-קבוצה $C \subseteq B$ של $N$ איברים היא פתרון לחידת המלכות אם לכל $Q_k(i_k, j_k), Q_l(i_l, j_l) \in C$ (כאשר $k \ne l$) מתקיימים כל 4 התנאים:
1. לא באותה עמודה: $i_k \ne i_l$
2. לא באותה שורה: $j_k \ne j_l$
3. לא באותו אלכסון: $i_k + j_k \ne i_l + j_l$
4. לא באותו אלכסון נגדי: $i_k - j_k \ne i_l - j_l$
2. ייצוג בחשבון מודולרי יהא $A = \{0, 1, 2, \dots, N^2-1\}$. תת-קבוצה $B \subseteq A$ של $N$ איברים היא פתרון אם לכל $x, y \in B$ כך ש-$x \ne y$ מתקיימים:
1. לא באותה עמודה: $x \not\equiv y \pmod N$
2. לא באותה שורה: $\lfloor x/N \rfloor \ne \lfloor y/N \rfloor$
3. לא באותו אלכסון: $(x \bmod N) + \lfloor x/N \rfloor \ne (y \bmod N) + \lfloor y/N \rfloor$
4. לא באותו אלכסון נגדי: $|(x \bmod N) - \lfloor x/N \rfloor| \ne |(y \bmod N) - \lfloor y/N \rfloor|$
3. קבוצה יציבה מקסימלית – Maximum Stable Set (14.3) בגרף $G=(V,E)$, קבוצת צמתים $V' \subseteq V$ היא יציבה (stable) אם אין ב-$E$ אף קשת המחברת שני צמתים ב-$V'$.
• נייצג כל משבצת בלוח כצומת ב-$V$ ($|V|=N^2$), ותהא ב-$E$ קשת בין כל שני צמתים שנמצאים על אותה עמודה, אותה שורה או אותו אלכסון (יחס איום).
• פתרון: כל קבוצה יציבה $V' \subseteq V$ בגודל $\sqrt{|V|} = N$.
4. קליק מקסימלי – Maximum Clique (14.4) בגרף $G=(V,E)$, קבוצת צמתים $V' \subseteq V$ היא קליק (clique) אם בין כל שני צמתים ב-$V'$ יש קשת ב-$E$ המחברת אותם.
• נייצג כל משבצת כצומת ב-$V$, ותהא ב-$E$ קשת בין כל שני צמתים שאינם נמצאים על אותה עמודה, אותה שורה או אותו אלכסון (יחס אי-איום, הגרף המשלים ל-14.3).
• פתרון: כל קליק $V' \subseteq V$ בגודל $\sqrt{|V|} = N$ ($\binom{N}{2}$ קשתות).

    classVariableNames: '' poolDictionaries: '' category: 'OOD-8Queens'

// --- 15.3 ארבע מתודות הפרוטוקול החיצוני ---
Queen >> setColumn: aColumn neighbor: aQueen
    column := aColumn.
    neighbor := aQueen

Queen >> firstSolution
    neighbor firstSolution.
    row := 1.
    ^ self moveToNextNonAttackedRow

Queen >> nextSolution
    ^ self advance and: [self moveToNextNonAttackedRow]

Queen >> result
    "add row to the list"
    ^ neighbor result addLast: row; yourself

// --- 15.4 שלוש מתודות התקשורת הפנימית ("פרטיות") בין המלכות ---
Queen >> advance
    row = 8
        ifTrue: [
            neighbor nextSolution ifFalse: [^ false].
            row := 0].
    row := row + 1.
    ^ true

Queen >> moveToNextNonAttackedRow
    [neighbor canAttack: row x: column]
        whileTrue: [self advance ifFalse: [^ false]].
    ^ true

Queen >> canAttack: testRow x: testColumn
    | columnDifference |
    columnDifference := testColumn - column.
    ((row = testRow
        or: [row + columnDifference = testRow])
        or: [row - columnDifference = testRow])
            ifTrue: [^ true].
    ^ neighbor canAttack: testRow x: testColumn

🔍 4 דגשים קריטיים על מתודות Queen למבחן:

  • ב-canAttack:x:: לא בודקים column = testColumn כי לכל מלכה הוקצתה עמודה ייחודית באתחול! נבדקים רק 3 תנאים: אותה שורה (row = testRow), אלכסון עולה (row + columnDifference = testRow) ואלכסון יורד (row - columnDifference = testRow).
  • ב-advance: כאשר row = 8 המלכה מבקשת משכנתה neighbor nextSolution (Backtracking!), מאפסת row := 0 ואז מקדמת row := row + 1 כך שהיא מתמקמת בשורה 1 מול הסידור החדש של שכנותיה.
  • ב-result: חובה לסיים ב-; yourself כי addLast: row מחזירה את row ולא את ה-OrderedCollection!
  • ב-nextSolution: השימוש ב-and: [...] העצל מבטיח שאם self advance החזיר false (אין יותר פתרונות), החיפוש ייעצר מיד.

16.1–16.2 ★ הכללה ללוח N×N (מלכודת משתנה המחלקה N!) וללוח תלת-ממדי N×N×N

הכללה ל-$N$ מלכות על לוח $N \times N$: הצב $N$ מלכות על לוח שחמט $N \times N$ כך שאף מלכה אינה מאיימת על מלכה אחרת. בפתרון מונחה העצמים הקבוע 8 מופיע ב-2 מקומות בלבד: בלולאת 1 to: 8 ב-Board>>initialize ובבדיקה row = 8 ב-Queen>>advance.

🚨 שאלת הבחינה הקלאסית: מלכודת משתנה המחלקה N בהכללת הלוח ל-$N \times N$!

אם נגדיר ב-Board משתנה מחלקה משותף classVariableNames: 'N' ומתודת מחלקה Board class>>N ^ N, וב-Queen>>advance נבדוק row = Board N, מה יקרה בהרצת הקוד הבא? 

board1 := Board new.
board2 := Board new.
board1 initialize: 5.   "קובע N := 5 ויוצר ב-board1 שרשרת של 5 מלכות"
board2 initialize: 1.   "דורס את משתנה המחלקה המשותף וקובע N := 1!"
board1 solve.           "ידפיס: No Solution. !"

הסבר: משתנה מחלקה N משותף לכל מופעי Board! הקריאה board2 initialize: 1 דרסה את N ל-1, ולכן כשמריצים board1 solve, 5 המלכות של board1 בודקות row = Board N מול 1, לא מתקדמות מעבר לשורה 1, ואי אפשר להציב 5 מלכות בשורה אחת בלבד!
הפתרון התקני: לשמור את גודל הלוח כמשתנה מופע פרטי (boardSize) ב-Board ובכל Queen!

🧊 חידת המלכות המרחבית – לוח שחמט תלת-ממדי $N \times N \times N$:

הגדרת הבעיה התלת-ממדית: הצב $N^2$ מלכות על לוח שחמט תלת-ממדי $N \times N \times N$ כך שבכל אחד מהמישורים אף מלכה אינה מאיימת על מלכה אחרת. עבור שתי מלכות $Q_1(i, j, k)$ ו-$Q_2(\text{row}, \text{col}, \text{lev})$, הקוד ב-Smalltalk המזהה איום מרחבי: 

dx := (row - i) abs.
dy := (col - j) abs.
dz := (lev - k) abs.
((dx = 0) and: [ dy = 0 ]) ifTrue: [ ^ true ].   "1. איום לאורך ציר המפלסים (אותה שורה ואותה עמודה)"
((dx = 0) and: [ dy = dz ]) ifTrue: [ ^ true ].  "2. איום אלכסוני במישור המקביל לצירים y-z (אותה שורה)"
((dx = dz) and: [ dy = 0 ]) ifTrue: [ ^ true ].  "3. איום אלכסוני במישור המקביל לצירים x-z (אותה עמודה)"
((dx = dy) and: [ dx = dz ]) ifTrue: [ ^ true ]  "4. איום באלכסון מרחבי תלת-ממדי או במישור x-y (כאשר dz=0)"

* מימוש פתרון לחידה התלת-ממדית ב-Smalltalk: מכיוון שיש להציב $N^2$ מלכות על לוח $N \times N \times N$, מקצים לכל מלכה זוג קבוע של (row, column) (סה"כ $N^2$ מלכות בשרשרת מקושרת מהמלכה $(N,N)$ ועד QueenTerminator), והמלכות מנהלות משא ומתן על בחירת המפלס lev ($1 \dots N$) תוך בדיקת אי-איום באמצעות 4 תנאי האיום המרחביים שהוגדרו לעיל!

מספר הרמות במערכת שפות מייצגות מאפייני הארכיטקטורה והמגבלה שהובילה לרמה הבאה
רמה 1: מערכת של עצמים בלבד Self מערכת "שטוחה" ללא מחלקות כלל. כל עצם מתאר את עצמו (טבלה המתאימה שמות לערכים) ומופעים חדשים נוצרים באמצעות שכפול (Cloning) של עצם קיים (אב-טיפוס `Novel Prototype`).
רמה 2: מערכת עצמים בת 2 רמות Eiffel יש עצמים ויש מחלקות המתארות אותם, אך אין מטה-מחלקות: המחלקות אינן מיוצגות בזמן ריצה, אינן עצמים ואינן מגיבות להודעות.
רמה 3: מערכת עצמים בת 3 רמות Smalltalk-76, Little Smalltalk הדרישה המינימלית למערכת סמולטוק: גם העצמים וגם המחלקות הם עצמים, ויש רק מטה-מחלקה אחת בלבד (היורשת מ"עצם" והיא מופע של עצמה). המגבלה: לכל המחלקות יש מבנה והתנהגות זהים (למשל מימוש משותף של new) ואי אפשר להגדיר מתודות-מחלקה או משתני-מחלקה פרטניים לכל מחלקה!
רמה 4: מערכת עצמים בת 4 רמות LOOPS, ObjVlisp (הרחבות Lisp) מאפשרת לכל מחלקה להגדיר מטה-מחלקה פרטית משלה (כגון Meta Novel עם n_novels, או לשתף מטה-מחלקה), וכל המטה-מחלקות הן מופעים של "המטה-מחלקה הגנרית" היחידה (שהיא מופע של עצמה).
רמה 5: מערכת בת 5 רמות – Explicit Metaclass Squeak, Smalltalk-80 לכל מחלקה (לרבות Metaclass עצמה!) יש מטה-מחלקה שמתארת רק אותה; כל המטה-מחלקות (לרבות Metaclass class) הן מופעים של Metaclass, ונוצר גרף ירושה של מטה-מחלקות החופף את גרף הירושה של המחלקות הרגילות!

18.8–18.11 ★ 10 חוקי המודל ב-Squeak, היררכיה מקבילה ואיתור blue ו-new

📜 10 החוקים של מודל העצמים והמטה-מחלקות ב-Squeak (סעיפים 18.8–18.14):

חוקים 1–5 (מודל העצמים הבסיסי): 1. כל דבר הוא עצם.
2. כל עצם הוא מופע של מחלקה.
3. לכל מחלקה יש מחלקת-על.
4. הכל קורה באמצעות שליחת הודעות.
5. איתור מתודות נעשה במעלה היררכיית הירושה (למשל שליחת class ל-translucentBlue מחפשת ב-TranslucentColor → Color → Object).
חוקים 6–10 (חוקי המטה-מחלקות – סעיפים 18.10–18.14): 6. כל מחלקה היא מופע יחיד של מטה-מחלקה אנונימית (Color class).
7. היררכיית מטה-מחלקות מקבילה להיררכיית המחלקות!
8. כל מטה-מחלקה יורשת מהמחלקה Class ומהמחלקה Behavior.
9. כל מטה-מחלקה היא מופע של המחלקה Metaclass.
10. המטה-מחלקה של Metaclass (Metaclass class) היא מופע של Metaclass!
  • הודעות תשאול למחלקה כעצם ובחינה ב-Inspector:
    • הודעות למחלקה: subclasses (מערך תתי-מחלקות), allSuperclasses (אוסף כל מחלקות-העל), instVarNames (מערך משתני המופע של המחלקה), allInstVarNames (מערך כל משתני המופע כולל אלו שנורשו ממחלקות-העל).
    • מעקב שרשרת superclass של מטה-מחלקה: מה מחזיר הביטוי TranslucentColor class superclass superclass? הוא מחזיר את Object class (המטה-מחלקה של Object).
    • שליחת מתודת מחלקה בירושה (TranslucentColor blue): כששולחים TranslucentColor blue, החיפוש מתחיל ב-TranslucentColor class, עולה ל-Color class, מוצא שם את blue ומחזיר צבע כחול אטום רגיל (Color blue). מה אפשר לעשות כדי ש-TranslucentColor blue תחזיר צבע כחול שקוף במקום כחול רגיל? להגדיר מחדש (Override) את המתודה blue במטה-מחלקה TranslucentColor class (למשל ^ super blue alpha: 0.5)!
    • כותרת חלון ה-Inspector: בכותרת ה-Inspector רשום תמיד שם המחלקה של העצם הנבחן (ולא שם העצם): כשבוחנים את Color blue הכותרת היא Color, וכשבוחנים את המחלקה Color הכותרת היא Color class!

🏆 שאלת הבחינה הקלאסית: מסלול איתור המתודה TranslucentColor new:

  1. המקבל (self): עצם המחלקה TranslucentColor.
  2. התחלת החיפוש במטה-מחלקה של המקבל: החיפוש מתחיל ב-TranslucentColor class (ולא במחלקת-העל Color!).
  3. טיפוס במעלה היררכיית המטה-מחלקות: TranslucentColor class → Color class → Object class → Class → ClassDescription → Behavior.
  4. מציאת new ב-Behavior: המתודה new ממומשת ב-Behavior, ומכיוון שהיא יוצרת ומחזירה מופע של self (שהוא המקבל המקורי TranslucentColor), העצם המוחזר הוא מופע של TranslucentColor (ולא של Behavior)!

18.12–18.15 ★ מחלקות הליבה (Behavior, ClassDescription, Class, Metaclass), נוסחאות ודבר סוף

1. Behavior (יורשת מ-Object) יוצרת את המינימום הנדרש להידור מתודות וליצירת מופעים ולהרצתם (שומרת מצביע ל-superclass, מילון מתודות, פורמט מופעים, ומתודות היצירה new, basicNew, new:, basicNew:).
2. ClassDescription (יורשת מ-Behavior) מחלקה מופשטת המוסיפה פעולות כגון הגדרת פרוטוקולים, שמות למשתני מופע, תיעוד ומעקב אחרי שינויים. ממנה יורשות שתי אחיות: Class ו-Metaclass!
3. Class (יורשת מ-ClassDescription) יוצרת את ההתנהגות המשותפת לכל המחלקות הרגילות: מטפלת בשם המחלקה, משתני מחלקה, מאגרים משותפים ויצירת תתי-מחלקות. ממנה יורשת Object class (וב-Squeak דרך ProtoObject class)!
4. Metaclass (יורשת מ-ClassDescription) מגדירה את התנהגותן המשותפת של מטה-מחלקות (יצירה ואתחול של מופע יחיד שהוא עצם המחלקה, אתחול משתני מחלקה וכו'). כל המטה-מחלקות (כולל Metaclass class!) הן מופעים של Metaclass!

🎓 נוסחאות זהב לפיצוח שאלות שרשור class ו-superclass במבחן (סעיפים 18.14–18.15):

  • • C superclass class == C class superclass → true  (עבור כל מחלקה C שאינה שורש העץ, לפי חוק 7 של ההיררכיה המקבילה!)
  • • Object superclass → ProtoObject (או nil בשורש)   |   Object class superclass → Class (דרך ProtoObject class)
  • • Metaclass superclass → ClassDescription   |   Class superclass → ClassDescription
  • • Metaclass class → Metaclass class   |   Metaclass class class → Metaclass  (חוק 10: קשר מופע מעגלי!)
  • • Metaclass class superclass → ClassDescription class  (לפי חוק 7, כי מחלקת-העל של Metaclass היא ClassDescription!)
